## 3. 落盘规则（本项目）

### 3.1 四维分流

按维落盘，**不要混用**：

- **需求 / 方案 / 计划 / 一次性的修复记录** → `01-Projects/<主题夹>/`；同一主题追加文件，不要平行再开一夹。
- **长期有效的规范、模板、手册** → `02-Areas/` 根下单文件，**不建主题子夹**。
- **外部事实、数据、剪藏** → `03-Resources/` 根下单文件，**不建主题子夹**。
- **失效/被取代的内容** → `04-Archives/` 根下单文件，**不建主题子夹**；整个主题夹作废时整夹迁入。

### 3.2 命名

| 位置 | 格式 | 示例 |
|---|---|---|
| Projects 主题夹 | `R{YYYYMMDD}-{两位序号}-{主题名}` | `R20260820-01-上游DSH版本适配` |
| 主题夹内文件 | `{两位序号}-{类型}_{标题}.md`，索引固定为 `00-README.md` | `08-修复_dsh0.1.0-rc8破坏.md` |
| 其余三维文件 | `{YYYYMMDD}-{两位序号}-{主题}.md` | `20260914-06-上游兼容规范_跟随最新官方DSH.md` |

- `YYYYMMDD` **不是建文件的当天**，按维取不同的日期：
  - `01-Projects` 主题夹 → 该**主题的起始日**（迁移历史主题时用原起始日，演进顺序才看得出来）
  - `03-Resources` / `04-Archives` → 该**内容自身的来源日期**（外部资料采集日 / 该归档物的事发日）
  - `02-Areas` → 该**规范的确立日**（迁移既有文档时用迁移日，原始日期写进文件头的 `**日期**`）
- 主题夹内 `00-README.md` 必填：说明本夹是什么、每个文件记什么、当前状态。
- 类型词表（固定，勿自创）：`讨论` `需求` `方案` `实施计划` `验证` `总结` `待办` `事实` `修复` `分析` `评审` `事件` `架构提案` `教程`。

### 3.3 状态的真源

- **主题夹内的管线文档是历史记录**，其内部行号/数字口径停留在写作当日，**不作为当前状态的真源**，也不要为了"对齐现状"去改历史记录。
- **当前状态的真源只有一个**：`01-Projects/R20260914-01-演进总览/`（路线图 / 演进时间线 / 待办总表）。
- 已知的历史文档口径冲突集中登记在 [01-Projects/R20260914-01-演进总览/04-文档勘误台账.md](01-Projects/R20260914-01-演进总览/04-文档勘误台账.md)，按需增量修正。

### 3.4 写作

- 全部中文；代码标识符、文件路径、commit message 保持英文（见 AGENTS.md §1）。
- 现状/差距类内容必须基于代码与 DSH 事实并标注来源（`文件:行号` 或命令输出），禁止臆测。
- 同一事实只维护一份，其余用相对链接引用。
- 每份文档头部带 `**日期**: YYYY-MM-DD` 与 `**状态**:`。

## 4. CLI（PARA 工具）

```bash
para-structure cp "主题名"     # 在 01-Projects 下新建 R{今天}-xx-主题名 夹
para-structure doctor --json  # 检测四维目录 / .gitkeep / 本 README / AGENTS 锚点是否完整
para-structure pack para      # 打包整个 PARA 工作区
```

新增主题请用 `cp`，不要手写 `mkdir`；历史主题需要保留起始日期时，用 `cp` 建好后立即改名。
