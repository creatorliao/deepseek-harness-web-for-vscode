# 多窗口资源占用与省资源实践

**日期**: 2026-09-18 ｜ **状态**: 当前
**定位**: 回答"频繁开关 / 同时开多个 VS Code 窗口时，DeepSeek Harness（dsh）会不会重复起服务、各占多少资源、彼此共用什么"，并给出可执行的省资源做法。
**核实基线**: 扩展 `0.5.3` ｜ dsh `0.1.5-rc.2` ｜ VS Code `1.105.1` ｜ Windows 11 ｜ 实测时刻 2026-09-18 15:13–15:57

> 事实来源分三类，正文逐条标注：**代码事实** → `src/xxx.ts:NN`（写当日行号）；**实测** → 当次命令输出（复现命令见 §8）；**推断** → 明确写"推断"，未实测的一律不当事实用。

---

## 0. 一句话结论

**一个 VS Code 窗口 = 一个独立的 `dsh web` 服务进程。**

- 窗口之间**不共享服务**：没有锁文件、没有端口注册表、没有"发现已有实例就复用"的代码；每个窗口自己 spawn 一个，端口由 OS 分配。
- 窗口之间**只共享数据目录** `$DSH_HOME`：会话、工作区注册表、设置、凭据是同一份。
- 所以"多开窗口"= **多份服务**：每份常驻 **0.2–0.7 GB**、冷启动约 **17 s**（本机实测），关掉窗口才释放。
- 省资源的第一原则：**少开窗口**（同一窗口内的多会话 / 多面板不额外起服务），**不用时显式"停止"**。

## 1. 机制：一个窗口一个服务

### 1.1 链路（代码事实）

| 环节 | 事实 | 来源 |
|---|---|---|
| 激活 | 激活事件是 `onStartupFinished` → **每个窗口**的扩展宿主都会跑一次 `activate()` | `package.json:166-168` |
| 实例 | `activate()` 里 `manager = new DshServerManager()`，模块级单例，**一个窗口一个** | `src/extension.ts:25,32` |
| 是否自启 | 只有 `workspaceState` 里 `dsh.wasRunning === true` 才自动启动 | `src/extension.ts:111,153-157`；`src/workspaceTracker.ts:26-28` |
| 标记存放 | `dsh.wasRunning` 存 `workspaceState`——**按工作区文件夹 key，不按窗口** | `src/extension.ts:22,94-99`；实测见 §2.4 |
| 启动 | spawn `dsh web --port 0 [--no-open]`，`cwd` = 工作区根 | `src/serverManager.ts:498-524`；`src/commands.ts:30-33` |
| 端口 | `--port 0` → OS 分配空闲端口，所以多实例不会撞端口 | `src/serverManager.ts:498`；实测 8911 / 7971 / 10110 |
| 同窗口重复启动 | `start()` 发现子进程还活着就直接返回已有 URL，**不会重复 spawn** | `src/serverManager.ts:456-460` |
| 数据目录 | 扩展**从不传** `dshHome`（只传 `cwd` 与可选 `dshBin`）→ 每个实例都用同一个 `$DSH_HOME` | `src/commands.ts:30-33`；`src/serverManager.ts:495-496` |
| 跨窗口复用 | **不存在**：`src/` 内无 lock / singleton / `globalState` / 端口发现逻辑（全仓 grep 确认） | — |
| 关闭 | 关窗口 / 重载窗口 → `deactivate()` → `manager.stop()`（POSIX `SIGTERM`；Windows `taskkill /T /F` 整棵树） | `src/extension.ts:245-252`；`src/serverManager.ts:872-908` |
| 就绪预算 | 就绪超时 60 s；历史上 4.3–7.9 s 出就绪行 | `src/serverManager.ts:79,84-88` |

### 1.2 什么动作会"又起一个"

| 动作 | 会起新服务吗 | 依据 |
|---|---|---|
| 新窗口打开一个**从未跑过**的文件夹 | ❌ 不会（界面显示"启动"按钮） | `src/extension.ts:111,153-157`；`src/dshUi.ts:102-123` |
| 新窗口打开一个 `wasRunning=true` 的文件夹 | ✅ **会，且不用你点任何东西** | 同上 |
| 同一窗口重载窗口（Reload Window / 装扩展后重载） | ✅ 会：先杀旧服务，再冷启动一个新的（端口也换） | `src/extension.ts:153-157,245-252` |
| 同一个文件夹开第二个窗口 | ✅ 会（第二个实例；两个实例还会选中同一条会话，见 §7） | §1.1 标记按文件夹 + `src/serverManager.ts:780-798` |
| 同一窗口再点"启动" | ❌ 不会（复用） | `src/serverManager.ts:456-460` |
| 同窗口换文件夹 | ✅ 旧服务被杀；新的按**新文件夹**的标记决定起不起 | `src/extension.ts:153-157,245-252` |
| 关编辑器标签面板 / 关侧边栏视图 | ❌ **不杀服务**（设计如此：会话与服务都不受影响） | `src/dshPanel.ts:152-159` |
| 关闭窗口 | ✅ 杀掉该窗口的服务 | `src/extension.ts:245-252` |

## 2. 本机实测（2026-09-18）

**场景**：本机当时正好开着 **2 个 VS Code 窗口**（`d:\code\deepseek-harness-web-for-vscode` 与 `d:\Users\liaohai1\Desktop\黄圣碧课程沟通`），两个窗口都跑着 DSH。

### 2.1 进程账

| 进程 | 父进程 | 监听 | 常驻内存 | 说明 |
|---|---|---|---|---|
| `node` PID 1984 | cmd ← 扩展宿主 5260 ← 窗口 A | `127.0.0.1:8911` | **671 MB** | 正在跑会话（本次调查就是在它里面执行的） |
| `node` PID 3148 | cmd ← 扩展宿主 15056 ← 窗口 B | `127.0.0.1:7971` | **260–404 MB**（两次采样） | 空闲 |
| `runner.js` 子进程 ×3 | 各自的 dsh | — | **57 MB / 个** | 每次工具调用临时起一个 |

- 端口存活 + 鉴权围栏实测：两个端口对无 Cookie 的 `GET /` 都返回 **401**（与 [DSH 上游事实速查](../03-Resources/20260914-01-DSH上游事实与协议速查.md) §2 一致）→ **两个端口是两台独立服务**，不是同一台的多入口。
- 空闲 CPU：PID 3148 在 5 s 窗口内 0.06 s（≈1.2%）；PID 1984 同期 1.44 s，但它当时正在执行本调查的命令，**不代表空闲基线**。
- 当时**没有**任何孤儿 dsh 进程：2 个窗口 ↔ 2 个服务，一一对应。

### 2.2 空实例冷启动成本（POC，测完已清理）

在临时目录起一个全新的 `dsh web --port 0 --no-open`（不建会话、不连接）：

| 指标 | 实测 |
|---|---|
| 从 spawn 到打出就绪行 | **17.1 s** |
| 就绪瞬间 RSS | 464 MB |
| 空闲 20 s 后 RSS | **210 MB** |
| 启动期间累计 CPU | 17.3 s |

> 结论：**"起一个服务"这件事本身的代价 ≈ 17 s 启动 + 17 s CPU + 空闲 0.2 GB**，与你聊了多少无关；会话变大后才涨到 0.4–0.7 GB（对照 §2.1）。
> 17.1 s 明显高于代码注释里 2026-09-14 记的 4.3–7.9 s，当次机器上还有另一个 DSH 会话在跑重活（CPU 竞争），**不能当作当前版本的绝对基线**。

### 2.3 上下文：VS Code 自己也不便宜

同一时刻 `Code.exe` 共 **21 个进程 / 4,386 MB**（2 个窗口）。即：两个 dsh 服务合计约 **1.1 GB**，约占 VS Code 自身开销的 **1/4**——多开窗口时 dsh 是**可感知但非最大**的一块。

### 2.4 `wasRunning` 标记的分布（省资源的关键点）

扫本机 VS Code 工作区存储（`%APPDATA%\Code\User\workspaceStorage\*\state.vscdb`，键 = 扩展 id）：

| 标记值 | 工作区数 | 说明 |
|---|---|---|
| `true` | **10** | 其中 **2** 个是当前开着的窗口；**其余 8 个没有对应进程**——标记残留 |
| `false` | 4 | 上一次是"停止"状态 |

> 实测事实：`dsh.wasRunning` **每个文件夹一条**（同一文件夹的两个窗口读同一条），而不是每个窗口一条。
> **推断**（未实测成因）：窗口关闭时 `stop()` 触发的 `workspaceState.update(false)` 是浮动 Promise，扩展宿主可能在写盘前就退出，于是标记留在 `true`。
> **实际影响**：这 8 个文件夹**只要你打开就会自动起一个服务**（约 0.2 GB / 17 s），而你以为"只是打开看看"。这是省资源时最容易踩的坑。

## 3. 共用什么、不共用什么

| 维度 | 同机多窗口 | 依据 |
|---|---|---|
| 服务进程 | ❌ **各自一份** | §2.1 两个 PID / 两个端口 |
| 监听端口 | ❌ 各自 OS 分配 | `src/serverManager.ts:498`；实测 8911 / 7971 |
| 启动令牌 & 浏览器 Cookie | ❌ 各自一套（Cookie 名绑定 authority `host:port`） | [上游事实速查](../03-Resources/20260914-01-DSH上游事实与协议速查.md) §2 |
| `$DSH_HOME`（会话 / 工作区注册表 / 设置 / 凭据） | ✅ **同一份**（共享带来的冲突面见 [多实例共享存储的冲突面](20260918-02-多实例共享存储的冲突面.md)） | `src/commands.ts:30-33`（不传 `dshHome`）；实测两实例子进程内 `DSH_HOME=D:\Users\liaohai1\.dsh` |
| 前端资产缓存（`globalStorage/dsh-dist`） | ✅ 同一份磁盘缓存，但**每个 webview 各加载一遍** | `src/dshUi.ts:91-93` |
| 每个界面（侧边栏视图 / 每个编辑器标签） | ❌ 各自一个 webview + 一条到本窗口服务的 WS 桥，**隐藏不释放** | `src/extension.ts:48-54`；`src/dshPanel.ts:72-81`；`src/dshPanel.ts:170-185` |

补充实测：`DSH_HOME` **不是**用户级环境变量（`[Environment]::GetEnvironmentVariable("DSH_HOME","User")` 为空），是 dsh 自己解析默认 home 后注入进程环境的；扩展不覆盖它，所以"同一份数据目录"是同机所有 dsh 实例的默认行为。

## 4. 资源账：每多开一份要付多少

| 项 | 量级（本机实测） | 备注 |
|---|---|---|
| 一个空闲 dsh 服务 | **≈ 0.21 GB** | 空实例 20 s 后 210 MB |
| 一个在跑的 dsh 服务 | **0.26–0.70 GB** | 与会话长度、插件、上下文规模相关 |
| 冷启动一次 | **≈ 17 s + 17 s CPU** | 每次重载窗口都要重付 |
| 每个 DSH 界面 | 一个 webview 渲染进程 + 一条 WS 桥 | 内存未单独归因（见 §7） |
| 每次工具调用 | **≈ 57 MB** 的 `runner.js` 子进程 | 临时进程，任务结束即退 |

**推论（可直接用来做取舍）**：开 4 个窗口跑 DSH ≈ 多付 **1–3 GB** 常驻内存 + 每次重载 4×17 s 启动；而同样的 4 个项目放进**一个窗口**用多会话/多面板，服务只有一份。

## 5. 省资源做法（按收益排序）

### 5.1 少开窗口；多项目用"一个窗口 + 多会话/多面板"

- **做法**：需要同时处理多个项目时，优先在一个窗口内用 `＋新建会话` 或"在编辑器打开"开多个面板；确实要并排两个项目时，接受"两个窗口 = 两份服务"的代价。
- **依据**：DSH 本身支持单实例多会话并行（见 [产品定位与边界](20260914-09-产品定位与边界.md) 的架构定盘）；多面板各自绑一个会话、互不影响。
- **代价**：一个窗口里会话多了，侧边栏列表变长；跨项目的会话要切工作区才看得到（见 [跨端会话可见性](../01-Projects/R20260918-02-跨端会话可见性/00-README.md)）。

### 5.2 同一个文件夹不要开两个窗口

- **做法**：一个文件夹只开一个窗口；需要第二块屏幕时走 §5.5。
- **依据**：`wasRunning` 按文件夹存（§2.4）→ 第二个窗口也会自动起服务；且两个实例的 `ensureWorkspaceSession()` 会选中**同一条**会话（`src/serverManager.ts:780-798` 复用任意已绑定会话）。同一条会话的并发写会被上游的会话级写锁拒绝（不会写坏，已实测），但**工作区登记会互相覆盖**——完整机制与实测见 [多实例共享存储的冲突面](20260918-02-多实例共享存储的冲突面.md)。
- **代价**：无。

### 5.3 不用时显式"停止"，别只关界面

- **做法**：命令面板 → `DeepSeek Harness: 停止`（命令 id `deepseek-harness-for-vscode.stop`）。
- **依据**：`stop()` 会把状态推到 `stopping/stopped`，`wasRunning` 随之写回 `false`（`src/extension.ts:94-99`）→ 下次重载**不会**自动起（`src/extension.ts:153-157`）。只关编辑器标签或侧边栏**不会**停服务（`src/dshPanel.ts:152-159`）。
- **代价**：下次要用得手动"启动"（或点状态栏）。

### 5.4 少重载窗口

- **做法**：把"重载窗口"当成付费操作——每次都是"杀服务 + 17 s 冷启动 + 全插件树重新加载"。
- **依据**：§1.2 + §2.2；`src/serverManager.ts:84-88` 记录了"dsh 每次调用都要加载整棵插件树"。
- **代价**：无。

### 5.5 第二块屏幕用"在浏览器打开"复用同一个服务

- **做法**：在已跑着服务的窗口执行 `DeepSeek Harness: 在浏览器打开`（`deepseek-harness-for-vscode.openBrowser`），用浏览器当第二个客户端——**共用同一台 dsh**，不再多付一份服务。
- **依据**：该命令用带 token 的 `browserUrl`（`src/serverManager.ts:426-428`；`src/commands.ts:81-90`），浏览器换到自己的 Cookie 后即是同一服务的另一个客户端（扩展描述里"shared instance with the browser"就是这个意思，`package.json:4`）。
- **代价 / 注意**：⚠️ 启动器里显示的那行 URL 是**不带 token** 的基址，直接粘到浏览器会 401；端口每次重启都会变，重启后要**重新点一次**该命令（Cookie 按 `host:port` 存，约 30 天）。

### 5.6 关掉不用的 DSH 界面

- **做法**：不看的编辑器标签面板及时关；次级侧边栏视图也别常驻。
- **依据**：每个界面 = 一个 webview（`src/extension.ts:48-54`、`src/dshPanel.ts:72-81`），且 `retainContextWhenHidden: true` → **隐藏不等于释放**，前端状态与 WS 桥都留着。
- **代价**：重开面板要重新组装一次前端（秒级）。

### 5.7 定期清点"没人认领"的 dsh 进程

- **做法**：偶尔跑一次 §8.1 的清单命令；发现父进程已消失的 `node ... dsh ... web` 就 `taskkill /PID <pid> /T /F`。
- **依据**：正常关窗口会杀子进程（`src/extension.ts:245-252`）；强制结束编辑器 / 扩展宿主崩溃时 `deactivate()` 不保证执行（**推断，本次未观察到残留**）。
- **代价**：无。

### 5.8 想让不同用途的数据隔离（不是省资源，是防串味）

- **做法**：在**用户级环境变量**里设 `DSH_HOME` 并重启编辑器，同机所有 dsh 实例就会换到另一个 home。
- **依据**：扩展不传 `dshHome`（`src/commands.ts:30-33`），子进程继承扩展宿主环境 → 用户级变量生效。
- **代价**：换 home = 换掉全部历史会话与凭据，属于数据搬家；同一时刻多个 home 会让"会话在另一处看不见"的困惑重演。

## 6. 一条判断口诀

> **看窗口数，不看面板数。**
> 面板/会话是免费的（服务一份、端口一个）；窗口是收费的（每窗口一份 0.2–0.7 GB + 17 s 启动）。

## 7. 风险与未验证项

| # | 项 | 状态 |
|---|---|---|
| R1 | **同一文件夹的两个实例同时驱动同一条会话**（`ensureWorkspaceSession` 会返回同一 sessionId，两个服务各自持有内存态、写同一份 JSONL）→ 是否互相覆盖 / 交错写 | ✅ **已实测（2026-09-18，隔离 `$DSH_HOME` 双实例）**：第二个实例的写入被**会话级跨进程写锁**直接拒绝（`SessionAlreadyOwnedError: … is already owned by an active write handle`），**对话内容不会被写乱**；但同一文件夹还会带来**工作区登记互相覆盖** → 见 [多实例共享存储的冲突面](20260918-02-多实例共享存储的冲突面.md) |
| R2 | 强制结束编辑器 / 扩展宿主崩溃后的**孤儿进程** | 本次**未观察到**（2 窗口 = 2 服务）；强杀场景未复现 |
| R3 | **webview 渲染进程的内存归因**：本机每窗口 2 个渲染进程（192+628 MB / 386+362 MB），但命令行里没有可区分"工作台 vs webview"的标记，DSH 那一份**没能单独切出来** | 未做 |
| R4 | `wasRunning` 残留的成因（关窗口时写盘丢失） | **推断**；观测事实是 10 个 `true` 中只有 2 个有对应进程 |
| R5 | 多根工作区（Add Folder to Workspace）会改变工作区标识 → 自动恢复行为如何 | 未验证 |
| R6 | 本文所有内存/耗时数字随 dsh 版本、会话规模、机器负载漂移 | 数字属"当次实测"，复现命令见 §8 |

## 8. 复现命令

### 8.1 进程与端口（PowerShell）

```powershell
# 现在有几个 dsh 服务、各自内存、父进程是谁
Get-CimInstance Win32_Process -Filter "Name='node.exe'" |
  Where-Object { $_.CommandLine -like '*bin.js*web*' } |
  ForEach-Object {
    $p = Get-Process -Id $_.ProcessId
    "{0} ppid={1} {2:N0}MB start={3}" -f $_.ProcessId, $_.ParentProcessId, ($p.WorkingSet64/1MB), $p.StartTime
  }

# 它们监听哪些端口
$pids = (Get-CimInstance Win32_Process -Filter "Name='node.exe'" |
  Where-Object { $_.CommandLine -like '*bin.js*web*' }).ProcessId
Get-NetTCPConnection -State Listen | Where-Object { $pids -contains $_.OwningProcess }
```

### 8.2 每个工作区的 `wasRunning` 标记

```python
# python 8.2：扫 %APPDATA%\Code\User\workspaceStorage\*\state.vscdb
import sqlite3, os, glob, json
base = os.path.expandvars(r"%APPDATA%\Code\User\workspaceStorage")
for d in glob.glob(os.path.join(base, "*")):
    sv = os.path.join(d, "state.vscdb")
    if not os.path.exists(sv):
        continue
    con = sqlite3.connect("file:%s?mode=ro" % sv.replace("\\", "/"), uri=True)
    row = con.execute("SELECT value FROM ItemTable WHERE key=?",
                      ("creatorliao.deepseek-harness-for-vscode",)).fetchone()
    if row:
        wj = os.path.join(d, "workspace.json")
        uri = json.load(open(wj, encoding="utf-8")).get("folder") if os.path.exists(wj) else "?"
        print(uri, "->", row[0].decode("utf-8", "replace")[:120])
```

### 8.3 冷启动成本（**测完必须清理**）

```powershell
$tmp = Join-Path $env:TEMP "dsh-poc-cwd"; New-Item -ItemType Directory -Force $tmp | Out-Null
$sw = [System.Diagnostics.Stopwatch]::StartNew()
$p = Start-Process "$env:APPDATA\npm\dsh.cmd" -ArgumentList "web","--port","0","--no-open" `
     -WorkingDirectory $tmp -RedirectStandardOutput "$env:TEMP\poc-out.txt" `
     -RedirectStandardError "$env:TEMP\poc-err.txt" -PassThru -WindowStyle Hidden
# 轮询 $env:TEMP\poc-out.txt 出现 "dsh web: " 即就绪；记录 $sw.Elapsed
# 量 RSS：Get-Process -Id <node 子进程 pid> | % WorkingSet64
taskkill /pid $p.Id /T /F     # ← 必须执行，否则会留下一个常驻服务
```
