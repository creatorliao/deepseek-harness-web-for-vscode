## 2. 构建与验证（改完必须跑）

| 改动 | 必跑命令 | 通过标准 |
|---|---|---|
| TypeScript（`src/**`） | `npm run compile` | **零 issue**，含 `info` 级 |
| 纯 JS（`media/bridge-client.js`、`scripts/*.js`、`test/*.js`） | `node --check <file>` | 无语法错误 |
| 任何代码改动 | `npm test`（= `tsc -p ./ && node --test`） | 全绿（当前 **93/93**） |
| 发布前 | `npm run package` + 见发布清单 | vsix 可安装、激活正常 |

**零缺陷门**：以上任一命令返回错误 → 任务状态为 **Blocked**，先修完再继续，不得"先提交后修"。

## 3. 代码质量纪律

1. **Surgical Changes（只碰必须碰的）**：不"顺手改进"相邻代码、注释、格式；不重构没坏的东西；跟随既有风格。发现无关死代码 → **说出来，不要删**。每一行改动都要能追溯到本次请求。
2. **Partial Formatting**：只格式化新增/修改的代码。**全局重排格式是禁止的**。
3. **最小实现**：能 50 行写完的不要写 200 行；不做单次使用的抽象；不加没被要求的"可配置性"。自检问句："资深工程师会说这过度设计了吗？"
4. **括号平衡自检**：提交任何改动前，确认本次编辑涉及的 `{}` `[]` `()` 成对。
5. **符号依赖自检**：删除/改名符号前，先 `grep` 全部引用点，确认不会破坏其他文件。
6. **契约变更**：若改动函数的异常、返回语义、前置条件或副作用，**先** grep 全部调用点，逐一确认与新行为兼容，再动代码。
7. **延迟必须给证据**：任何"暂不处理"必须引用**具体阻塞项**（上游 API 未开放、跨模块迁移计划、Phase 门未开）。**严重级别（P1/P2）、"风险低"、"工作量太大"都不是延迟理由。**
8. **语言切换自检**：在 TS / JS / webview 注入 JS 之间切换时，逐条核对语法与类型假设，不要沿用上一种语言的直觉。

## 4. 依赖纪律

- **能用 Node 内置就不加包**：`node:http`、`fetch`、`WebSocket`（≥22）、`node:test`、`node:assert`、`node:path` 等。
- 必须新增依赖时，先说明理由与体积/供应链影响。
- 当前运行时依赖只有 **`ws`**（`src/bridgeHost.ts` 的 WebSocket 服务端）。它**必须**留在 `package.json` 的 `files` 白名单内（`node_modules/ws/**`）——历史上漏掉一次导致安装版激活崩溃，见 [修复记录](../01-Projects/R20260817-01-桥架构与IDE内嵌/11-修复_vsix缺少ws依赖.md)。
- 依赖最小化带来一个可验证的红利：整仓单测零第三方测试框架。

## 5. 安全基线（不可弱化）

- dsh 服务**只能**绑 `127.0.0.1` / `localhost`；`dsh web` **禁止** `--host 0.0.0.0`。
- 扩展代发请求必须保持"普通 Node 请求"形态，**不得**弱化 DSH 的 `/api` 信任围栏（不要伪造 Origin/sec-fetch-site 绕过，也不要去掉围栏）。
- 不做 SSRF：代发目标限定回环地址，拒绝任意外部 URL。

## 6. 开发环境搭建（含本机实测注意项）

```sh
npm install --cache .npm-cache     # 首次
npm run compile                    # tsc
npm test                           # 单测
npm run watch                      # 开发时增量编译
# 然后 F5 启动 Extension Development Host
```

**实测注意项**（2026-09-14，Windows + DSH 受限沙箱）：

| 现象 | 原因 | 处理 |
|---|---|---|
| `npm install` 报 `spawn EPERM` | npm 执行 lifecycle script 需要 piped stdio，受限沙箱禁止 | 本仓依赖全是纯 JS/类型包，用 `npm install --ignore-scripts` 即可 |
| `node --test` 报 `spawn EPERM` | `node:test` 默认每个测试文件 spawn 一个子进程 | 用 `node --test --test-isolation=none`；若测试内部还要 spawn（如 `serverManager.test.js` 起 fake dsh），需在非受限模式下运行 |
| `tsc` 报找不到 `@types/node`、`vscode` | `node_modules` 未安装 | 先装依赖；`out/` 里的旧产物不构成"已安装" |
