# 扩展与 Webview 规范

**规范确立**: 2026-09-14 ｜ **状态**: 生效 ｜ **适用**: `src/` 里的 VS Code 扩展代码、侧边栏/面板 webview、`media/` 注入脚本

> 本文件把"踩过的坑"固化为规则。每条规则后面都挂着一次真实故障——**违反它不是风格问题，是会复现的 bug**。

---

## 1. Webview UI

| 规则 | 原因（真实故障） |
|---|---|
| **禁止硬编码颜色**，一律用 VS Code 主题变量（`var(--vscode-editorWidget-background)`、`var(--vscode-button-background)` 等），深浅色交给主题自动决定 | 硬编码颜色在浅色主题下不可读 |
| **CSP 强制**：必须带 CSP（`default-src 'none'` + 最小授权），`connect-src 'none'` 由传输桥全拦截兜底 | 见 `src/documentAssembly.ts` 的 CSP 常量；这是安全基线 |
| **CSP 源列表必须覆盖上游真实用到的 URL 方案**：DSH 客户端的图片预览走 `URL.createObjectURL`（`blob:` URL 继承页面 origin，不匹配 `cspSource`）→ `img-src` 必须含 `blob:` | 不放行则**粘贴的截图全是破图**（[修复记录 14](../01-Projects/R20260817-01-桥架构与IDE内嵌/14-修复_面板内图片不显示与内测声明反复出现.md)）。同一处收紧还压着文件上传的 `Worker`（`worker-src`）与 HTML 预览的 iframe（`frame-src`），改动 CSP 前先按该记录 D 节核对上游用法 |
| **外部资源必须同源或 `data:`**，不得裸跨源引用字体/脚本/样式 | 跨源 CORS 失败导致面板白屏 |
| **按钮尺寸必须显式内联**，不要依赖 flex 子项宽度计算链；侧边栏内任何按钮都要显式给宽高 | 全局 `button { width: 100% }` 会把列表行内的图标按钮挤出可视区（[修复记录](../01-Projects/R20260819-02-多会话管理/09-修复_会话按钮横向偏移.md)） |
| **错误与加载态必须覆盖**：starting / error / stopped 三态覆盖层，禁止白屏无提示 | — |
| **可访问性**：按钮有 `aria-label` 或文本，焦点顺序自然，键盘可操作 | — |
| 贴合 VS Code 设计语言：字号、间距、控件、状态栏文案遵循惯例；面板高度自适应 | — |

## 2. 宿主 ↔ Webview 通信时序（**最容易踩**）

**规则**：`webview.html = …` 赋值后**不要立即** `postMessage`——页面还没注册 `message` 监听器，消息会被静默丢弃。

- 正确做法：页面加载完成后**主动发握手**（如 `view-ready`），宿主收到后再推送当前状态。
- 状态类 UI 必须有**握手或轮询兜底**：不能只依赖"状态变化时推送"这一条路径。
- 原因：侧边栏状态曾长期卡在 "Starting…"（切换侧边栏或笔记本唤醒后触发），因为状态消息早于页面监听器注册（[修复记录](../01-Projects/R20260817-01-桥架构与IDE内嵌/12-修复_侧边栏状态卡在Starting.md)）。

**规则**：任何"只推不拉"的状态同步，都要问一句"错过了这次推送怎么办"。

## 3. 传输桥

- webview **不能**直连 DSH 的 `/api`：跨源请求会被信任围栏 403 拒绝。
- 所有 `fetch` / WebSocket / 剪贴板调用必须经 `postMessage` 桥转给扩展宿主，由宿主以**普通 Node 请求**代发。
- **不得**为了让 webview 直连而弱化围栏（见 [工程规范](20260914-01-工程规范.md) §5）。
- `media/bridge-client.js` 是**纯 JS**，不经过 tsc：改动后必须 `node --check media/bridge-client.js`。

### 3.1 往上游富文本编辑器写入：不得用同步 DOM 读判定成败（2026-09-17 新增）

**规则**：向 DSH 的 composer（Lexical）写入文本后，**不能**在同一个 tick 里读 DOM 判断"写没写进去"——编辑先进编辑器状态，DOM 在之后的 tick 才提交。必须**等待**并以**内容**为判据（"那段文本在不在输入框里"），而不是"DOM 字符串变没变"。

**为什么**（两次真实误判，[修复记录](../01-Projects/R20260917-01-目录树拖拽到Composer/11-修复_右键插入报失败导致重复两条引用.md)）：

1. **同步读**：paste 已经派发、文本正在路上，同步读仍是旧值 → 判失败 → 宿主写剪贴板并提示"请按 Ctrl+V 粘贴" → **用户一粘贴就变成两条**（实测：真机探针里文本已 1 次，代码却回报 `ok:false`）。
2. **"变了"判据**：粘贴若替换的是一段**内容完全相同**的选区，DOM 字符串根本不变 → 同样误报失败 → 同样骗用户去粘贴。

**配套**：这类写入路径**必须**有"对着真机跑"的探针，而不是只有假 DOM 单测——`npm run probe:composer`（`scripts/probe-composer-insert.js`：起真实 `dsh web` + headless Chromium，注入真 `bridge-client.js`，实测写入次数与回报）。假 DOM 会把"异步提交"这一关键性质抹平，测出来的是假设而不是被测对象。

## 4. i18n（已简化为单一语言）

**本扩展只做简体中文**（2026-09-14 决定）：维护 8 份额外翻译的成本远大于收益。

- **一切用户可见文案写在 `src/i18nStrings.ts`** 的中央字符串表里（每行只有 `zh` 一个字段），代码里用 `t("key")` 取用；**不要**在代码里硬编码面向用户的字符串。
- **清单文案**（命令标题、设置描述）写在 `package.nls.json` —— 内容也是中文，且**不再有 `package.nls.<locale>.json`**，这样任何 locale 都不会回落到英文。
- `test/i18n.test.js` 会校验：每个键都有非空中文值、且**不含多余语言列**（防止合并时把删掉的语言带回来）。
- 命令标题等**标识符**本身保持英文，不翻译。
- 仓库文档一律中文。

## 5. 生命周期与资源

- 所有订阅、监听器、定时器必须挂到 `context.subscriptions` 或对应的 `DisposableStore`，并确保 `dispose` 时解除——**历史上漏解除导致关闭窗口时报 DisposableStore 错误**。
- 子进程必须优雅退出：先 SIGTERM，超时后强杀；Windows 要杀**整棵进程树**（`taskkill /T /F`），否则 `cmd.exe` 包装器会留下孤儿 `node` 进程。
- 面板与 dsh 进程的状态必须收敛到单一状态机，不允许多处各自维护"是否在运行"。

## 6. 面板与多会话

- 面板堆叠打开（`ViewColumn.Active`），不做平铺窄视图。
- 归档会话时**同时关闭**其面板；默认面板绑定 IDE 工作区会话，确保它也能被关闭。
- 恢复多个面板时，dist 资产缓存下载必须**防并发踩踏**（否则出现空面板）。
- 每个面板绑定一个会话，面板标题跟随会话标题。

### 6.1 两种界面形态与"单一路由点"

DSH UI 有**两种承载形态**，由设置 `deepseekHarness.openTarget` 决定默认走哪个（`src/openTarget.ts`）：

| 形态 | 实现 | 位置 |
|---|---|---|
| **次级侧边栏视图**（默认） | `src/chatView.ts` —— `WebviewViewProvider` | 右侧次级侧边栏，结构上钉死在主侧边栏对面 |
| **编辑器标签页** | `src/dshPanel.ts` + `src/sessionPanels.ts` | 编辑器区，可多开 |

**铁律**：

1. **所有"打开 DSH 界面"的路径必须走 `extension.ts` 的 `openUi()` 这一个路由点**。历史上这些路径各自散落（`panels.open(...)` 硬编码在四处），导致任何"默认开在哪里"的改动都会漏掉其中几条。
2. **两个形态必须共用同一套底层**：`documentAssembly`（抓取/改写/注入）、`BridgeHost`（http/ws/剪贴板转发）、`dshUi.ts`（覆盖层 + 主题探测 + dist 缓存路径）。**不要为其中一个形态复制这些实现** —— 它们都接受 `vscode.Webview`，与"面板还是视图"无关。
3. **`setSession()` 与 `show()` 必须分开**：前者只绑定不抢焦点（用于每次 ready 的后台同步），后者才聚焦。后台重启时抢焦点是明确的 bug。
4. **dist 缓存在两个形态之间共享**（同一个 `globalStorage/dsh-dist`），但 `asWebviewUri` 必须**逐 webview** 计算——每个 webview 是独立 origin。
5. **reveal 侧边栏要用容器命令** `workbench.view.extension.<容器id>`，**不要**用 `workbench.action.toggleAuxiliaryBar`（后者只切整个 part 的显隐，可能露出用户留在那儿的别的容器）；且必须 best-effort（命令可能因容器为空而不可用，不能因此阻断打开流程）。
6. `package.json` 的 `viewsContainers.secondarySidebar` 的 `id` **必须**与 `src/openTarget.ts` 的 `CHAT_VIEW_CONTAINER` 一致 —— `test/openTarget.test.js` 会交叉校验这两处，改一处必须改另一处。

## 7. 提交前自检（本规范专属）

- [ ] 新增按钮是否显式给了尺寸？
- [ ] `webview.html` 赋值后是否还有裸 `postMessage`？
- [ ] 新增/修改的订阅是否有对应的 `dispose`？
- [ ] 新增用户文案是否写进了 `src/i18nStrings.ts`（只有 `zh` 一项，不要加语言列）？
- [ ] 是否有硬编码颜色？（唯一例外：注入进上游页面的浮层——那里没有 VS Code 主题变量，见 `bridge-client.js` 的拖拽提示条注释）
- [ ] `media/bridge-client.js` 改动是否过了 `node --check`？
- [ ] 若改动涉及**往上游编辑器写入**：是否按 §3.1 用"等待 + 内容判据"，并跑过 `npm run probe:composer`？
