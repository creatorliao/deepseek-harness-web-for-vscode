## 二、现状与证据

**现象 1：活动栏上出现名字都叫「DeepSeek Harness」、但没有图标的孤儿条目。**

本机 VS Code 1.105.1 的 `state.vscdb`（`%APPDATA%\Code\User\globalStorage\state.vscdb`）里，
`workbench.activity.placeholderViewlets` 同时有**三个**本扩展的容器：

| 容器 id | name | 有没有 iconUrl |
| --- | --- | --- |
| `workbench.view.extension.deepseek-harness` | DeepSeek Harness | **有**（`.../creatorliao.deepseek-harness-for-vscode-0.6.0/media/icon.svg`） |
| `workbench.view.extension.dsh` | DeepSeek Harness | 无 |
| `workbench.view.extension.dsh-panel` | DeepSeek Harness | 无 |

而 `workbench.activity.pinnedViewlets2` 里这三条**全都是 `pinned: true`**：

```text
{"id":"workbench.view.extension.deepseek-harness","pinned":true,"visible":false,"order":9}
{"id":"workbench.view.extension.dsh","pinned":true,"visible":false,"order":9}
{"id":"workbench.view.extension.dsh-panel","pinned":true,"visible":false,"order":20}
```

对应的隐藏状态键也还在，且用的都是旧 view id：

```text
workbench.view.extension.dsh.state.hidden       -> [{"id":"dsh.chatView","isHidden":false}]
workbench.view.extension.dsh-panel.state.hidden -> [{"id":"dsh.webview","isHidden":false}]
workbench.view.extension.deepseek-harness.state.hidden -> [{"id":"deepseek-harness.view","isHidden":false}]
```

当前版本 `package.json` 只贡献 `deepseek-harness` 与 `deepseek-harness-chat` 两个容器，
所以 `dsh` 与 `dsh-panel` 是**旧版容器 id 的孤儿 pin**：容器本体已经不在了，pin 还留着，
VS Code 就以「占位容器」的形式渲染它们，**没有图标可渲染，于是显示默认图标**。
截图里那两个一样的"文档"图标，就是这两个孤儿占位项。

这与本仓 `AGENTS.md` §7.1 已记录的那次变更对得上：2026-09-14 扩展 id / 容器 id 改过，
原文写着「旧 id 的安装与设置不会自动迁移」。

**现象 2：拖拽功能对应的投放条是常驻 UI，用户关不掉。**

`package.json` 把投放条挂进**内置资源管理器容器**，而且没有 `when` 条件：

```json
"views": {
  "explorer": [
    { "id": "deepseek-harness.contextDrop", "name": "%view.contextDrop.name%", "icon": "$(add)" }
  ]
}
```

`package.json.nls.json` 里这个名字是「DSH 上下文（拖文件到此）」。
本仓 `docs/01-Projects/R20260917-01-目录树拖拽到Composer/07-待办_目录树拖拽到Composer.md` 的 `E3` 条，
当时就已经写明这个方案「会**新增一块常驻 UI**」；
`E-C` 条记录 v0.6.0 已采用该方案。

**现象 3：编辑器标签页形态会新开一个编辑器组。**

当前设置的 `deepseekHarness.openTarget` 是 `editorTab`。
`src/openTarget.ts` 的 `columnForRightSide()`：

```ts
export function columnForRightSide(groups: readonly { viewColumn: number }[]): number {
  if (groups.length <= 1) return VIEW_COLUMN_BESIDE;   // 只有 1 组时返回 ViewColumn.Beside
  return Math.max(...groups.map((g) => g.viewColumn));
}
```

VS Code 对 `ViewColumn.Beside` 的语义是**新开一组**，所以只有一个编辑器组时打开 DSH 界面，
编辑器区会从 1 列变成 2 列。

**现象 4：两个容器同名同图标。**

```json
"viewsContainers": {
  "activitybar":     [{ "id": "deepseek-harness",      "title": "DeepSeek Harness", "icon": "media/icon.svg" }],
  "secondarySidebar":[{ "id": "deepseek-harness-chat", "title": "DeepSeek Harness", "icon": "media/icon.svg" }]
}
```

两处 title 与 icon 完全相同，活动栏一个、次级侧边栏一个，hover 提示也分不出来。

**复现步骤**

1. 装 `creatorliao.deepseek-harness-for-vscode` 0.6.0，重载窗口。
2. 看左侧活动栏：除带鲸鱼图标的那个之外，另有名字同为「DeepSeek Harness」、无图标的条目。
3. 打开一个文件夹，看资源管理器：文件树下方常驻一条「DSH 上下文（拖文件到此）」。
4. 设置 `deepseekHarness.openTarget` 为 `editorTab`，只保留一个编辑器组，执行「在编辑器打开」。

**频率 / 影响面**：现象 1 是必现；现象 2 是必现且没有关闭入口；现象 3 在单编辑器组时必现。
只影响界面观感与布局，不影响 DSH 会话本身。

**证据**：上面 `state.vscdb` 的四个键原文；`package.json` 的 `contributes` 段；
`src/openTarget.ts` 的 `columnForRightSide()`；`07-待办` 的 `E3` / `E-C` 条。
截图见上文说明（**未附文件**，活动栏 hover 即可复现）。

## 三、期望结果与验收标准

| #   | 验收标准（可判定） | 怎么验 |
| --- | ------------------ | ------ |
| 1   | 活动栏上不再有名字是「DeepSeek Harness」却**渲染不出图标**的条目 | 重载窗口后数活动栏上名为 DeepSeek Harness 的条目，只剩带 `media/icon.svg` 的那一个；`state.vscdb` 的 `workbench.activity.placeholderViewlets` 里不再有 `workbench.view.extension.dsh` 与 `workbench.view.extension.dsh-panel` |
| 2   | 投放条可以在不卸载扩展的前提下关掉 | 把新开关设成关闭后重载窗口，资源管理器里看不到「DSH 上下文（拖文件到此）」；设回打开后能再次看到 |
| 3   | 投放条关掉时，拖拽能力仍有可达入口 | 关掉投放条后，命令面板里仍能执行「添加到 DSH 输入框」这一条，行为与原来一致 |
| 4   | 已有一个编辑器组时打开 DSH 界面，不新增编辑器组 | 单编辑器组下执行「在编辑器打开」，`View: Toggle Editor Layout` 或数编辑器列数，仍是 1 组；DSH 作为该组里的一个标签页出现 |
| 5   | 活动栏容器与次级侧边栏容器能一眼区分 | 分别 hover 两个图标，提示文字不是同一串 |

## 六、给接收方的提示

**为什么现在提**：现象 1 是旧版容器 id 变更留下的兼容遗留，用户没做任何操作就背上了两个关不掉、认不出的图标；
现象 2 是本仓自己在 `07-待办` 里已经写明的代价，现在由现场确认「这个代价我不接受」。
另外这一批诉求在待办里本来就挂着一条 `C-drop`：**用户确认是否保留右键入口**——本次可以一并拍板。

**建议落点与判断依据**

- 现象 1 → `src/extension.ts` 的 `activate()` 里做一次旧容器 id 的清理，或按本仓 §7.1 的对内原则
  把 `dsh` / `dsh-panel` 作为兼容别名继续贡献（避免 pin 变孤儿）。两种做法取舍要写进方案。
- 现象 2 → `package.json` 给 `deepseek-harness.contextDrop` 加 `when` 条件并在 `configuration` 里加开关；
  开关默认值需人拍板（默认开 = 现状，默认关 = 更尊重原界面）。
- 现象 3 → `src/openTarget.ts` 的 `columnForRightSide()`，以及 `src/dshPanel.ts` 里
  `viewColumn: vscode.ViewColumn = vscode.ViewColumn.Beside` 这个默认值。
- 现象 4 → `package.json` 两个容器的 `title` 与 `icon`。

**期望进入的阶段**：需求转换。现象 1 与现象 3 建议按缺陷处理，现象 2 与现象 4 建议按体验需求处理。
