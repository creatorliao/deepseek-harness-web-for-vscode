# 分析：数据外发与网络边界

**日期**: 2026-09-18 ｜ **状态**: 当前
**定位**: 逐层回答"它会不会把数据传到外部去"——插件自身、桥与本地服务、dsh 内核三层各发什么、去哪、何时、能否关闭，并记录一处桥围栏缺口。

---

## 1. 一句话结论

**插件自身不采集、不上报用户数据**；它唯一的对外网络请求是**查询 npm registry 上的 dsh 版本号**（匿名 GET，24h 一次，**目前无法关闭**）。业务数据（对话、文件内容、工具结果）在插件范围内**只走 `127.0.0.1`**。真正把内容送出本机的是 **dsh 内核**：① 模型请求本身（产品功能）；② 随请求携带的匿名安装 ID 头；③ **默认开启的 OTel 会话遥测**——仅在用户**显式提交反馈**时，把截至该反馈的**完整会话前缀**发往 DeepSeek 的遥测端点。**本插件既不新增这些外发，也不提供关闭它们的入口。**

## 2. 三层数据流

```
┌─ VS Code webview（DSH 前端，源 vscode-webview://） ─────────────┐
│  CSP: connect-src 'none'  ← 页面内不能直连外网（documentAssembly.ts:164）
│  fetch/WebSocket 被 bridge-client.js 劫持，只转发同源（:27-33,77）
└──────────────┬──────────────────────────────────────────────────┘
               │ postMessage（http / ws / clipboard）
┌──────────────▼─ 扩展宿主（Node，本插件）────────────────────────┐
│  BridgeHost → relayHttp / WsRelay → http://127.0.0.1:<port>     │
│  另有一条独立外发：GET https://registry.npmjs.org/...（版本检查）│
└──────────────┬──────────────────────────────────────────────────┘
               │ 本机 HTTP / WS（带 dsh 签发的会话 cookie）
┌──────────────▼─ dsh 内核子进程（上游，非本插件代码）────────────┐
│  → provider（DeepSeek 等）：对话/文件/工具结果 + 匿名 ID 头      │
│  → harness-telemetry.deepseeksvc.com：OTel 会话遥测（反馈触发）  │
└─────────────────────────────────────────────────────────────────┘
```

## 3. 第一层：插件自身——只有一处外发

| 项 | 事实 | 来源 |
|---|---|---|
| 目标 | `https://registry.npmjs.org/@deepseek-ai/dsh` | `src/versionCheckService.ts:13` |
| 请求 | `fetch(REGISTRY_URL, { signal })`——**无 headers、无 body、无 query、无 cookie、无 credentials** | `src/versionCheckService.ts:61` |
| 超时 | 5s（`FETCH_TIMEOUT_MS`），失败**静默跳过**（离线不打扰） | `src/versionCheckService.ts:14,58-59,80-81` |
| 频率 | **24h 一次**；结果缓存在 `workspaceState`（`dsh.latestVersion` / `dsh.nextVersion`）；先写"已检查"时间戳再发请求，避免慢请求反复重试 | `src/versionCheckService.ts:12,39-50` |
| 触发 | dsh 进入 `ready` 之后（**不阻塞界面**） | `src/extension.ts:143-146` |
| 用途 | 只用于启动器的升级提示；点升级时**只在终端预填命令，绝不自动执行** | `src/versionCheckService.ts:100-111,163-165` |
| 开关 | **没有**（硬编码，无设置、无环境变量） | 全仓无相关配置项 |
| 开发期 | `scripts/check-dsh-latest.js:15` 访问同一 URL，但只在开发者跑 `npm run check:dsh` 时执行，**不随扩展运行** | `scripts/check-dsh-latest.js:15` |

**发出去的是什么**：一个**不含任何用户数据**的 GET。HTTP 层不可避免会暴露出口 IP、TLS SNI、时间与 Node fetch 的默认 User-Agent——这是任何网络请求的共性，不是本插件额外收集。

**全仓证据**：grep `telemetry|analytics|sentry|posthog|track(` 在 `src/` 与 `media/` **无匹配**；扩展也**不读取** VS Code 的 `telemetry.telemetryLevel`。

**唯一的浏览器跳转**：命令"在浏览器中打开"用 `vscode.env.openExternal` 打开**本机**带 launch token 的 URL（`src/commands.ts:81-90`）——把令牌交给系统浏览器，不出本机。

## 4. 第二层：桥与本地服务——围栏现状

### 4.1 已生效的边界

| 边界 | 事实 | 来源 |
|---|---|---|
| 只连本机 | 服务器基址来自 `dsh web` 的就绪行 `dsh web: http://127.0.0.1:<port>/?token=…` | `src/serverManager.ts:67` |
| 端口由 OS 分配 | 固定 `--port 0`，不接受外部指定 | `src/serverManager.ts:498` |
| 页面无法直连外网 | webview CSP `connect-src 'none'`；`default-src 'none'` | `src/documentAssembly.ts:158-167` |
| 只转发同源 | `isSameOrigin()` 不成立就走原生 `fetch`（再由 CSP 拦住） | `media/bridge-client.js:27-33,77` |
| 只发路径 | 转发给宿主的 `url` 是 `url.pathname + url.search` | `media/bridge-client.js:99-105` |
| 鉴权 | `/api` 请求与 WS 升级都带 dsh 签发的会话 cookie | `src/bridgeCore.ts:39,72`、`src/bridgeHost.ts:23` |

**顺带记录一个数据面（非外发）**：webview 可经桥读写系统剪贴板（`src/bridgeHost.ts:61-76`）——这是设计内的本地能力（DSH 前端要复制代码块），不是外发通道，但属于"数据能离开页面"的路径，审计时应知情。

### 4.2 ⚠️ 缺口：宿主侧未校验转发 URL

`relayHttp` 用**字符串拼接**构造目标：`serverBase + msg.url`（`src/bridgeCore.ts:35`），`WsRelay.open` 同理（`src/bridgeCore.ts:72`）——**都不校验 `msg.url` 的形状**。

**实测（2026-09-18，Node 内置 URL 解析）**：

```
new URL("http://127.0.0.1:53443" + "/api/x")        → host = 127.0.0.1:53443   ✅ 预期
new URL("http://127.0.0.1:53443" + "https://evil.com/") → 抛 Invalid URL      ✅ 挡住
new URL("http://127.0.0.1:53443" + "@evil.com/")    → host = evil.com         ❌ 绕过
```

`@` 让整段变成 URL 的 userinfo，主机名被替换成 `evil.com`——**这是有效 URL，请求会真的发出去**。

**当前是否可达**：**不可达**。桥的正常路径只发 `pathname + search`（`media/bridge-client.js:102`），构造不出 `@` 开头的主机替换。要利用它，需要在 webview 内**先具备脚本执行能力**去 `postMessage` 一个手工构造的 `url`；而页面内容来自本机 dsh 服务，且 CSP 的 `script-src` 允许 `'unsafe-inline'`（`src/documentAssembly.ts:160`，为 boot manifest 注入所必需）。

**判定**：**风险等级低（现网不可达），但它违反了强制口径**——[AGENTS.md](../../../AGENTS.md) §7：「扩展只能向 `127.0.0.1`/`localhost` 代发请求」。这条口径目前靠**客户端自觉**（bridge-client 只发 path），**不靠宿主校验**；而宿主是信任边界所在，一旦上游前端改动转发逻辑或页面出现注入点，围栏就只剩 CSP 一层。

**修法（C4，约 10 行）**：在 `relayHttp` 中把目标解析成 URL 后校验：`origin` 必须等于 `serverBase` 的 origin、协议必须是 `http:`，否则直接拒绝；`WsRelay.open` 同样校验 `path` 以 `/` 开头且不含 `@` 与 `://`。改动不影响正常路径。

## 5. 第三层：dsh 内核——真正的内容外发（上游行为）

以下均为**上游 `@deepseek-ai/dsh` 0.1.5-rc.2**（本机全局安装，2026-09-18 读包内文件核实），**不是本插件的代码**。列出它们是因为用户问的"数据外发"，主体在这一层。

### 5.1 模型请求（产品功能本身）

对话内容、`@` 引用的文件内容、工具执行结果必然发往所配置的 provider。**这是 DSH 之所以是 DSH**；关掉它等于关掉产品。目的地由用户本机的 dsh 配置（`$DSH_HOME/settings.yaml`，本机实测存在）决定——**本插件不读取、不修改该配置**。

### 5.2 匿名安装 ID（随每个 provider 请求发送）

| 项 | 事实 | 来源 |
|---|---|---|
| 载体 | `$DSH_HOME/.anonymous-user-id`（本机实测：36 字符 UUID 文本行；默认 `~/.dsh/`） | `dsh-anonymous-user-id/README.md:12,40` |
| 生成 | `crypto.randomUUID()`，**不派生**自主机名/网络地址/git remote | 同上 `:66` |
| 发送 | 每个 DeepSeek provider 请求带 `x-deepseek-harness-user-id` 头 | 同上 `:36` |
| 重要 | **与遥测分享模式无关**：即使 `DISABLED`，配了自定义 gateway 也会收到该头 | 同上 `:124` |
| 重置 | 删除该文件 → 下次启动生成新 ID（当前进程仍用旧值） | 同上 `:40,125` |

### 5.3 OTel 会话遥测（**默认开启**）

| 项 | 事实 | 来源 |
|---|---|---|
| 是否默认挂载 | **是**——`dsh-base` 的默认组合里就有这一行 | `.../dsh-base/cordis.patch.yml:184-197` |
| 模式 | 默认 `FEEDBACK_ONLY`（可用 `DSH_TELEMETRY_MODE` 改；`DISABLED` 不构造任何传输） | 同上 `:187`；`dsh-session-telemetry-otel/README.md:34-35` |
| 端点 | 默认 `https://harness-telemetry.deepseeksvc.com/v1/logs`（可用 `DSH_TELEMETRY_OTLP_URL` 覆盖），gzip，单次超时 1s | 同上 `:190-192` |
| **触发条件** | **只有显式反馈**（文本反馈、评分/备注编辑、撤回）才释放**截至该反馈的完整权威会话前缀**；后续记录等待下一次反馈。模型请求、会话创建、恢复、插件挂载**都不授权捕获** | `dsh-session-telemetry-otel/README.md:12,34,65` |
| **导出内容** | `event.data` 原样：**消息内容、工具参数与结果、系统提示与工具 schema、todo 文本、压缩摘要、反馈文本、会话 `cwd`** | 同上 `:69` |
| 不含什么 | **provider 凭据**（API key 是构造参数、不是 session event，结构上不出现） | 同上 `:69` |
| 身份 | 资源属性带匿名 `user.id`（每批次一次） | 同上 `:87` |
| 脱敏 | **"部署方负责脱敏规则"**——即默认不带脱敏规则 | 同上 `:12` |
| 关闭方式 | `DSH_TELEMETRY_DISABLED` **任意非空值**（含 `"0"` / `"false"`）即禁用；由 launcher 给该行打 `disabled: true`（**配置文件本身关不掉这一行**） | `.../dsh/lib/profile-boot-Dk-7KqJc.js:174-190` |

### 5.4 opt-in 的会话日志上传（默认关）

`session-log-deepseek` 默认 `enabled: false`；开启后会把会话日志**后缀**作为 DeepSeek 请求的字段上传（`dsh_session_log`），并记录接收水位线。**默认不注册该字段**（`dsh-session-log-deepseek/README.md:30-32,37`）。

### 5.5 本插件与这些开关的关系

扩展 spawn 内核时只做两件事：`env = { ...process.env }`，以及可选地覆盖 `DSH_HOME`（`src/serverManager.ts:495-496`）。**既不设置、也不清除任何 `DSH_TELEMETRY_*` 变量**——所以内核的行为完全等于"用户在系统/启动环境里的设置状态"。**在 IDE 内无法关闭内核遥测**（改进建议见 [02 §3.2](02-分析_配置项必要性与改进建议.md)）。

## 6. 汇总：什么数据、去哪、何时、能否关

| # | 数据 | 目的地 | 触发时机 | 能否关闭 |
|---|---|---|---|---|
| 1 | 版本号查询（无用户数据） | `registry.npmjs.org` | 启动后 24h 一次 | ❌ **无开关**（建议 C2） |
| 2 | 对话 / 文件内容 / 工具结果 | `127.0.0.1` 本机 dsh | 交互即发 | 桥不可关，**也不该关** |
| 3 | 模型请求内容 | 配置的 provider（DeepSeek 等） | 每次模型调用 | 由 dsh 配置决定，本插件不介入 |
| 4 | 匿名安装 ID（HTTP 头） | provider baseURL | 每个 provider 请求 | ❌ 只能删 `.anonymous-user-id` 换新 ID |
| 5 | **会话前缀遥测**（含消息、工具结果、系统提示、cwd） | `harness-telemetry.deepseeksvc.com` | **仅用户显式反馈时** | `DSH_TELEMETRY_DISABLED`（**插件未暴露**，建议 C3） |
| 6 | 会话日志后缀 | DeepSeek API | 需 opt-in | 默认关 |

## 7. 若要"零外联"，可执行的清单

1. **关内核遥测**：在 VS Code **启动环境**里设 `DSH_TELEMETRY_DISABLED=1`（PowerShell：`$env:DSH_TELEMETRY_DISABLED=1; code`）。任意非空值都生效。
2. **关版本检查**：当前只能靠防火墙 / hosts 屏蔽 `registry.npmjs.org`（或只放行 `127.0.0.1` 与 provider 域名）。**扩展侧无开关**——这是建议 C2 的动机。
3. **匿名 ID**：无法用环境变量关闭（它随请求头发送）；删除 `~/.dsh/.anonymous-user-id` 只会换一个新 ID。**属上游行为，本插件无法关闭**。
4. **模型请求**：不可能关——关了就没有产品功能。企业场景应改为把 provider 指向自建 gateway（由 dsh 配置决定）。
