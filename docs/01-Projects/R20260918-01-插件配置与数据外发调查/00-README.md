## 3. 结论速览（四问四答）

1. **有哪些配置项**：只有 **3 个**——`deepseekHarness.themeSync`、`deepseekHarness.dshPath`、`deepseekHarness.openTarget`（`package.json:84-111`）。其余行为靠 6 个命令、1 个快捷键、2 个视图容器与环境变量驱动，**不是设置**。
2. **含义**：`themeSync` 控制是否把编辑器深浅色写进 DSH 设置；`dshPath` 是可选的可执行文件路径覆盖；`openTarget` 决定"自动打开"时 UI 落在次级侧边栏还是编辑器标签页。
3. **必要与否**：`dshPath` **必要**（自动探测可能选错）；`openTarget` **可选但成本极低**（两种形态都有真实场景）；`themeSync` **语义不完整**——`off` 只关掉了 `settings.update` 这一条 RPC，**关不掉 `matchMedia` shim**，内嵌 UI 仍会跟随 VS Code 主题，属于"看起来能用、实际半失效"的开关，建议整改而不是删除。
4. **会不会外发**：**插件自身只有一处外网请求**——`https://registry.npmjs.org/@deepseek-ai/dsh` 的版本查询（`src/versionCheckService.ts:13,61`），只发一个无 body/无查询串/无 cookie 的 GET，24h 一次，**且没有任何开关可以关闭**。业务数据（对话、文件内容）全部只走 `127.0.0.1`。**真正把内容送出本机的是 dsh 内核**：模型请求本身，以及默认挂载的 OTel 会话遥测（`FEEDBACK_ONLY`，仅在用户显式提交反馈时导出截至该反馈的完整会话前缀到 `https://harness-telemetry.deepseeksvc.com/v1/logs`）。本插件既不新增外发，也不提供关闭内核遥测的入口。
