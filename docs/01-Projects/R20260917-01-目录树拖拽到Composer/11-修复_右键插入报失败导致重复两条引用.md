# 修复 — 右键入口「写入成功却报失败」，用户按提示粘贴后变成两条 `@` 引用（重复引用）

**日期**: 2026-09-17
**扩展版本**: 影响 v0.5.0 / v0.5.1 → 修复 v0.5.2
**dsh 版本**: 适配 0.1.5-rc.2（前端 Lexical 提交时序，实测；非 dsh 破坏性变更）
**影响面**: 资源管理器右键「添加到 DSH 输入框（@ 引用）」——引用**确实写进了输入框**，但扩展回报失败并把引用复制到剪贴板 + 弹提示"请按 Ctrl+V 粘贴"；用户照着粘贴 → 输入框里出现**两条相同引用**。拖拽入口同源（同一个写入函数），但真机拖拽另有 VS Code 侧阻塞，见 `09-事实` 补充。
**范围**: `media/bridge-client.js`（写入层的成功判定）、`test/bridgeClient.test.js`（补异步提交回归）、`scripts/probe-composer-insert.js`（新增真机探针）、`package.json`（`probe:composer`）
**根因归属**: 本项目代码（写入层的成功判定与上游编辑器的提交时序不匹配）
**关联**: 探针即证据 [scripts/probe-composer-insert.js](../../../scripts/probe-composer-insert.js) ｜ 上游事实 [10-事实_DSH-Composer与提及机制.md](10-事实_DSH-Composer与提及机制.md)

## 现象

用户实测：资源管理器右键 →「添加到 DSH 输入框（@ 引用）」，输入框里出现**两条完全相同**的 `@路径`。

## 根因

写入层用**同步 DOM 读**决定成败，而 DSH 的 composer 是 **Lexical**：编辑先进编辑器状态、DOM 在**之后的 tick** 才提交。

**实测证据**（`node scripts/probe-composer-insert.js`，真实 `dsh web` + headless Chromium，dsh 0.1.5-rc.2）：

| 实验 | 结果 |
|---|---|
| A 只发合成 `paste` 事件 | **同步读不到变化**（异步提交）；400ms 后**恰好 1 次** |
| B 只用 `document.execCommand("insertText")` | 返回 `false`，同样异步；**不稳定**（一次 1 次、一次 0 次） |
| C **修复前的线上路径** | 文本**写了进去（1 次）**，回报却是 `{ok:false, reason:"rejected"}` |

链条于是变成：写入成功 → 同步读不到 → 判为失败 → `handleInsertResult()` 走失败分支：**写剪贴板 + 弹「未能写入…请按 Ctrl+V 粘贴」** → 用户粘贴 → **两条**。

还有第二条同源通路（同一判据的另一面）：`execCommand` 兜底被无谓触发。既然第一次判失败，代码会再发一次 `execCommand`；两次提交在较慢的环境里都落地就是两条。

**为什么单测没拦住**：`test/bridgeClient.test.js` 的假 composer 在 `dispatchEvent` 里**同步**改 `textContent`——它把"真实编辑器的异步提交"这一关键性质抹掉了，于是永远走不到失败分支。**用假 DOM 单测富文本编辑器的时序 = 测了个假设，不是被测对象。**

## 修复

`media/bridge-client.js` 的写入层重写为**"等待 + 按内容判定"**：

1. **不再同步读**：发 `paste` 后轮询等待 DOM 变化（40ms 一次，单步预算 paste 600ms / execCommand 400ms）。
2. **判据从"文本变了"改为"引用确实在输入框里"**（`draftContains`）。这条更准，且修掉了探针顺带发现的另一种误判：**当粘贴是"替换一段内容相同的选区"时，DOM 字符串完全不变而写入其实成功了**——用"变了"判定照样会误报失败，照样骗用户去粘贴。
3. 只有第一步确实没落地才走 `execCommand` 兜底；成功即回报 `ok:true`，宿主因此**不再**写剪贴板、**不再**提示粘贴。

## 验证

| 项 | 结果 |
|---|---|
| 真机探针（改后） | C：出现 **1 次**，回报 **`{ok:true, reason:"paste"}`** ✅ |
| 真机探针 D（页面侧拖拽链路） | `dragover`/`drop` 均被接管；`dsh-context-drop` 正确转发原始负载 ✅ |
| 单测 | `test/bridgeClient.test.js` **15/15**，新增两条：① 异步提交（30ms 后落）→ `ok:true`、**恰好 1 次**、**兜底未被触发**；② 完全不接受的 composer → 两次尝试后 `ok:false` |
| 全量 | `npm test` 通过（见 `05-验证`） |
| 用户真机复测 | ⏳ 待用户（右键插入应只见一条，且**不再出现**"请按 Ctrl+V 粘贴"提示） |

## 后续建议

- [ ] 用户真机复测右键入口：确认**只有一条**引用，且**没有**失败提示
- [ ] 用户确认拖拽时是否**按住过 Shift**（见 `09-事实` 的真机补充）；若按住 Shift 仍无反应 → 启用 `07-待办` 的 E3（TreeView 投放区）
- [ ] 上游 dsh 升级后跑一次 `npm run probe:composer`：确认 composer 锚点 `[data-composer-input]`、paste 命令绑定与**异步提交**时序未变
- [ ] 任何"往后端富文本编辑器写入"的新代码，一律按 [扩展与 Webview 规范](../../02-Areas/20260914-02-扩展与Webview规范.md) §3.1（新增）判定成败
