# 侧边栏打开入口与版式重排 — 需求

**日期**: 2026-09-15 ｜ **状态**: ⏳ 待用户批准 ｜ **来源**: 用户口述（2026-09-15）+ 界面截图评审 + 现有实现审计

> 本文件只回答"做什么"，**不含实现细节**（实现细节在 [02-方案](02-方案_侧边栏版式重设计.md)）。

---

## 1. 背景（现状事实）

侧边栏 = 活动栏里的 DeepSeek Harness 视图（`deepseek-harness.view`，`src/launcherView.ts`）。它当前把**高频动作**和**低频信息**平铺在一起，自上而下是：

1. 标题 + `extension v0.3.4`
2. 运行状态卡（绿点 + `dsh <版本> 运行中` + 服务 URL）
3. 更新提示按钮（有更新时才出现，全宽描边）
4. **在右侧面板打开**（primary，全宽、文字居中）
5. **在编辑器打开**（secondary，全宽、文字居中）
6. **停止 DeepSeek Harness**（secondary，全宽、文字居中）
7. **＋新建会话**（secondary，全宽）
8. 会话列表 + 归档区
9. 工作区路径（页脚）

问题（用户 2026-09-15 截图评审的结论）：

- **顺序与频率倒挂**：最该反复点的"打开 / 切会话"被状态、版本、更新压在下面；状态与更新是**被动信息**，却占了首屏最贵的位置。
- **"在哪里打开"是高频意图，却没有成组、没有主次**：三个入口（含要新增的浏览器）如果继续按现有样式往下堆，就是三个同等重量的全宽条，用户每次都要逐行读。
- **按钮内文字全部居中**：在窄栏里居中文字既浪费横向空间，也让相邻按钮难以扫读；缺少图标锚点。
- **运行控制与导航动作混在一起**：`停止`（改变进程状态）夹在"打开"入口中间。

## 2. 用户诉求（原话照录）

> 增加一个新功能：在侧边栏里面，现在已经有了"在右侧面板打开"和"在编辑器中打开"，也应该增加一个"在浏览器中打开"。其实这几个按钮的内容应该是左对齐或右对齐什么的，里面的版式稍微设计一下。

> 我觉得这部分你应该帮我好好设计一下：
> 1. "运行中"以及"更新"相关的按钮，对用户来讲，放在底部可能更合适一点。
> 2. "在哪里打开"这部分也是高频行为，目前的排版不太好。
> 请你作为一名资深的设计师和用户体验设计师，重新设计一下这部分，让整体更合理一点。

## 3. 需求清单

| # | 需求 | 说明 |
|---|---|---|
| **R1** | 侧边栏新增第三个入口「**在浏览器中打开**」 | 能力已存在（命令 `deepseek-harness-for-vscode.openBrowser`），本轮是把它**做成侧边栏里的一等入口**，与另外两个入口并列 |
| **R2** | 运行状态、更新提示、停止按钮**下沉到底部区域** | 位于会话列表之下；"状态"与"改变状态的动作"（停止）应就近成组 |
| **R3** | 三个打开入口**视觉成组、有主次** | 一个主入口（右侧面板，默认形态）+ 两个次入口（编辑器 / 浏览器）；三者文案对齐方向一致、字重/底色体现层级 |
| **R4** | 三个入口的文案**左对齐并带前置图标**（对齐口径的最终取值见方案） | 用户明确要求"左对齐或右对齐什么的"，本需求只锁定"统一、成组、可扫读"，具体取左取右由方案定 |
| **R5** | 高频内容上移，压缩纵向开销 | 会话区上移到首屏；"新建会话"不再独占一整行（与"会话"标题同行） |
| **R6** | **行为零回归** | 不改变 `deepseekHarness.openTarget` 的语义、不改任何命令 id / 设置键名、不改会话列表的既有交互 |

## 4. 验收标准

| # | 验收标准 |
|---|---|
| **A1** | 服务运行中时，侧边栏可见三个打开入口；点「在浏览器中打开」后，系统默认浏览器打开**带启动 token 的 URL**（行为与命令面板里的 `在浏览器中打开` 完全一致，不出现 401） |
| **A2** | 服务运行中时，`运行中`状态、更新提示、`停止`三者都出现在**会话列表之下**的底部区域 |
| **A3** | 三个入口在视觉上成组，且**只有一个**主入口；用户能在不读全文的情况下分辨主次 |
| **A4** | 侧边栏拖到最窄（≈170px）时，三个入口的文案**不溢出、不换行**（必要时省略号），图标不被裁切 |
| **A5** | 服务未运行 / 启动中 / 出错时，动作区**只有一个主操作**（启动或重试），不出现点了没反应的打开入口 |
| **A6** | 深浅两种主题下都用 VS Code 主题令牌取色，无新增硬编码颜色（品牌 logo 除外）；键盘焦点环可见 |
| **A7** | `npm run compile` 零 issue、`npm test` 全绿；`deepseekHarness.openTarget` 的自动化路径（启动 / 状态栏 / 点会话）行为不变 |

## 5. 非目标（本轮明确不做）

| 不做 | 原因 |
|---|---|
| 改 DSH 自身界面（官方侧边栏收纳等） | 与本需求无关，已在 [R20260914-02/04-方案](../R20260914-02-DSH内嵌原理与教程/04-方案_DSH界面调整与侧边栏收纳.md) 单独处理 |
| 改 `deepseekHarness.openTarget` 的取值与默认 | 会破坏既有用户的设置语义（AGENTS §7.1 对内兼容原则） |
| 重排会话列表行（行内的重命名/归档按钮、宽高、绝对定位） | 该处已有过修复（见 [R20260819-02/10-分析_会话按钮横向偏移_by-gemini.md](../R20260819-02-多会话管理/10-分析_会话按钮横向偏移_by-gemini.md)），本轮不碰，避免把修好的对齐再打破 |
| 新增设置项（如"默认打开方式"下拉、按钮顺序可配） | 未被要求；"不加没被要求的可配置性"（AGENTS §2） |
