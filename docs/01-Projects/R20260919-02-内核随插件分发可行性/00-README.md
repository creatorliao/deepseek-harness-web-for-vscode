# R20260919-02 · 内核随插件分发可行性

**起始**: 2026-09-19 ｜ **状态**: ✅ 调查已出结论（**待用户决策**：是否实施、选哪个方案） ｜ **属性**: 分析（证据类，无管线阶段）

## 本夹是什么

回答一个问题：**能不能、该不该把 DeepSeek Harness 作为插件的真实依赖随插件分发？** 目标是让"**机器上根本没装 DSH**"也能用，同时**不与已安装的 DSH 冲突**。

**背景（一句话）**：现状是扩展**读本机已安装的 dsh**（不打包、不安装，见 [04-Archives 调查报告](../../04-Archives/20260919-01-插件运行的内核与版本跟随关系调查.md)），所以**没装 dsh 的机器完全用不了**；而早期架构提案里"扩展内置依赖"这条（`09-架构提案_by-deepseek.md:220` 的第 ③ 顺位）**从未落地**，本次是重新评估它。

## 核心结论（四句）

1. **做得到，但不便宜**：CLI 包自身只有 **48 KB**，**222.6 MiB 全在依赖树**（25,471 个文件）。
2. **一个 vsix 覆盖不了三平台**：`koffi` / `sharp` 只装当前平台，`node-pty` 自带多平台 prebuilds——**必须分平台打包**。
3. **"随插件走"≠"自包含"**：dsh 运行期仍要在 `DSH_HOME` 里用 pnpm 管理 profile 插件树。
4. **最难的不是打包，是不冲突**：本机实测 `$DSH_HOME/profiles/node_modules` 是**跨安装源的 junction 池**（同时链到 npm 全局 dsh、**DSH Desktop**、**pnpm 全局**、一个开发 checkout）——两个不同来源的 dsh 共用同一个 `~/.dsh` 会**互相改写这棵树**。

**建议**：只要"没装 DSH 也能用" → **按需获取 + 内置仅作兜底**；只有"完全离线"才轮到打包，并需接受 6 平台链路与多编辑器体积占用。
