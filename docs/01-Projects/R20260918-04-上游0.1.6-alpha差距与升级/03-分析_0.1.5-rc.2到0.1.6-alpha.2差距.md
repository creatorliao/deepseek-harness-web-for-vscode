## 0. 结论先行（30 秒版）

**升级不会弄坏 VS Code 面板；要不要升，取决于你要不要那批新功能、以及能不能接受 alpha 通道的不稳定。**

三句话：

1. **差距是真实的**：官方最新是 `0.1.6-alpha.2`（2026-09-17 发布），比我们在用的 `0.1.5-rc.2`（2026-09-10）多了**两个版本、7 天**的改动——**新增 58 个包、移除 90 个、229 个包换版本**，是一轮实打实的大改。
2. **对本扩展零破坏**（实测，不是推断）：四个破坏面 A–D **全部未变**，baseline 登记的 9 个脆弱点**全部仍在**。面板能起来、认证能过、会话 RPC 能用、插件能加载。
3. **但代价有两项是真的**：① `alpha` 是官方**实验通道**，不稳定、不保证向后兼容；② 磁盘占用从 **222.9 MiB 涨到 560.6 MiB**（其中 **325.1 MiB 来自一个包**：Office 预览用的 LibreOffice）。

**顺带的好消息**：启动**快了约 3 倍**（实测中位数 10.3–11.3 s → 3.5–3.9 s），这在 VS Code 面板里是能直接感觉到的（面板启动等待时间少约 7 秒）。

## 4. 对本扩展（VS Code 内嵌面板）的影响 —— 实测

> **方法**：把两个版本的官方包分别装到**隔离目录**（`spike/pkgdiff/tree-051`、`tree-016`），用**扩展自己的** `DshServerManager` 起服务（`DSH_BIN` 指向隔离安装），逐面取证。**全程没有碰全局那棵 dsh 树**（AGENTS.md §8 铁律）。
> 命令：`node scripts/smoke.js`（长期脚本）+ `node spike/probe-surfaces.js <label> <bin.js> <scratch-DSH_HOME> <dsh.cmd>`（**本轮一次性探针，`spike/` 不入库**）。**不依赖探针的等价配方已内联在 [02-方案](02-方案_官方DSH0.1.6-alpha升级.md) 的 S2**，可原样复现本节结论。

| 同上 | `data-sidebar-collapsed` | 1 | 5 | ✅ 仍在（用得更多） |

> ⚠️ **token 仍在 ≠ 语义未变**。计数只能证明"锚点没被删掉"，不能证明行为一致。**真机面板渲染**（F5 起 Extension Development Host 看面板）本轮**未做**，登记为待验证——见 §6。

### 4.3 用户能直接感觉到的连带效应

| 效应 | 数据 | 用户体感 |
|---|---|---|
| **前端资源缓存可能每次都失效**（⚠️ 本次副产品发现，见 §3 P5） | boot `rev` **每次服务进程启动都重新生成** | 扩展按 `rev.txt` 比对判断缓存是否失效 → 每次重启内核后首次组装面板都可能重下 dist 树。**未实测到实际重下行为**，仅由代码判据推出 |
| **页面变大** | `index.html` 27,660 B → 31,188 B（**+12.8%**） | 无明显体感 |
| **磁盘占用翻 2.5 倍** | `node_modules` **222.9 MiB → 560.6 MiB**（+337.7） | ⚠️ **+325.1 MiB 全部来自 `@deepseek-ai/libreoffice-kit-win32-x64` 一个包**（Office 预览功能）【实测】 |
| **启动变快** | 就绪行中位数 **10,318 / 11,307 ms → 3,928 / 3,493 ms**（两次测量、顺序相反） | ✅ 面板启动等待少约 7 秒 |

**启动耗时测量条件**（可复核）：同一台机器、同一个隔离 `DSH_HOME`（已预热）、每个版本各 3 次取中位数、**正反两种顺序各测一轮**以排除 OS 缓存顺序偏差。命令：`node spike/measure.js` / `node spike/measure.js reverse`。

### 4.4 结构级变化（今天没破，但是未来的风险信号）

| 变化 | 事实 | 为什么值得记 |
|---|---|---|
| **Web 服务端框架整体更换** | 移除 `express` 全家桶 + `hono` + `@hono/node-server`（连同 85 个传递依赖）；包数 520 → 488 | `/api` 与静态资源是**我们的 B/C 面**。这次行为没变，但**服务端换过一轮**，下次变动风险更高 |
| **MCP SDK 升大版本** | `@modelcontextprotocol/sdk@1.30.0` → `@modelcontextprotocol/client@2.0.0` + `@modelcontextprotocol/core@2.0.0` | 用 MCP 的用户配置可能受影响 |
| **PTC 运行时长换代** | 移除 `dsh-code-runtime`、`dsh-code-runtime-worker-thread`、`dsh-workflow-worker-thread`；新增 `dsh-ptc-runtime`、`dsh-ptc-runtime-node`、`dsh-workflow-ptc` | 与 §2.4 第 6/7 条对应 |
| **新增 `dsh-client-ui-slots`** | 与官方"客户端 Session 相关 API 及 slot 有变化"对应 | 上游前端插件机制在动 |
| **HMR 收进自家** | 移除 `@deepseek-ai/cordis-plugin-hmr`，新增 `@deepseek-ai/dsh-hmr` | 内部重构 |

> 数据来源：`node spike/pkgdiff/diff-trees.js`（逐包版本比对，输出见 `spike/pkgdiff/tree-diff.txt`）。

## 5. 升级的价值与代价（决策依据）

### 升上去能得到什么

1. **启动快约 3 倍**——每天开面板都能感觉到（本次最普惠的收益）。
2. **面板内终端 + Office 预览 + 文件改动逐项审阅**——把"切窗口"的活儿收回 IDE 里，与本扩展"减少用户操作"的产品定位同向。
3. **插件管理页**——插件不再只能靠改配置。
4. **一批真实修复**——尤其 **Windows 控制台窗口闪现**、**启动失败终于能看懂原因**、**会话被占用时给出提示**。
5. **图片质量与 V4.1 适配**——直接影响回答质量。

### 升上去要付什么

1. **alpha 通道的实验风险**：官方自己把它放在 `alpha`、`latest`/`next` 都还没跟进。**随时可能在下个 alpha 里变**，且不属于任何"稳定承诺"。
2. **磁盘 +325 MiB**（Office 预览的 LibreOffice），且这是**必装**的传递依赖，不能只装一半。
3. **§2.4 的 15 条破坏性变更**：其中 2 条（旧官方根地址、V4 Flash 从默认模型列表消失）**最可能让普通用户感觉"坏了"**；1 条（Web 终端不受沙箱限制）**是安全语义变化**。
4. **前端资源缓存判据可能每次失效**（P5，需另开一轮核实）。
5. **不在扩展的兼容矩阵里**：升到 alpha 后，`check:dsh` 仍会报"已跟到最新"（因为它只看 latest/next）——**矩阵与实际安装不一致**，属自担风险区间。

### 一句话建议（决定权在用户）

- **想要稳定** → 停在 `0.1.5-rc.2`，等 `0.1.6` 进 `next`/`latest` 再升（那时本扩展的兼容矩阵也会正式登记）。
- **想要那批新功能、且能接受实验风险** → 可以升，**技术上没有障碍**（四破坏面实测全过）；升之前先按 §2.4 处理那两条配置类变更。
