# 需求：跨端会话可见性问题

**日期**: 2026-09-18 ｜ **状态**: 待用户确认
**定位**: 把用户的口述现象整理成可判定、可验收的问题陈述，并列出必须先确认的歧义点。

---

## 1. 用户原始诉求（照录，仅做断句）

> 我作为一个用户，在本机上有 Open，有 DeepSeek harness for VSCode、DeepSeek dsh desktop，我发现有一些在 VSCode 里面写的对话，去到 desktop 上面只会展示一部分。这是什么情况？为什么呢原有的东西好像不展示齐全，会不会有这种情况？它们两者之间的对话是怎么互相处理的？互相被引用了？我理解它应该是从同一个地方来读取的吧？

拆成 4 个可回答的问题：

| # | 问题 | 本夹答案位置 |
|---|---|---|
| Q1 | 为什么在 VSCode 写的对话到 desktop 只显示一部分？ | [03-分析_会话可见性根因.md](03-分析_会话可见性根因.md) §2–§4 |
| Q2 | 原有的东西是不是真的没展示齐全？ | 同上 §4（本机实测：76 个根会话不可见，数据完好） |
| Q3 | 两端对话怎么互相处理？互相引用吗？ | 同上 §3（不互相引用；共享同一份存储，靠 `cwd` 归属） |
| Q4 | 是不是从同一个地方读取的？ | 同上 §1（**是**，`$DSH_HOME` 相同） |

## 2. 现象拆解（关键歧义）

"只展示一部分"至少有**两种互不相同的解释**，根因、影响面、修法都不一样：

| 读法 | 具体表现 | 当前证据状态 |
|---|---|---|
| **A. 列表不全** | desktop 侧边栏的会话列表里，VSCode 里建过的一些会话**根本不出现**（标题都看不到） | ✅ **已证实**。本机 76 个根会话数据完好但不可见，机制已定位到上游代码行（见 `03` §2、§4） |
| **B. 内容不全** | 会话**能**在列表里找到，点开后对话只渲染出一部分（前面若干轮/某些工具输出缺失） | ❓ **未证实**。已排除两条常见嫌疑（见下），但未复现 |

对读法 B 已经**排除**的嫌疑（取证见 [04-事实_本机会话存储取证.md](04-事实_本机会话存储取证.md)）：

- **不是文件损坏**：386 个会话的头部全部解析成功，0 失败。
- **不是旧格式读不出**：磁盘上 `session.jsonl.zstd`（v0）与 `session.v3.jsonl.zstd`（v3）并存，读取器取"数值最高的一代"，v0 走**懒迁移**后正常读出（`dsh-session-persistence-jsonl/lib/index.js:3160-3191`、`:2486-2511`）。

读法 B 仍然**站得住的候选**（尚未验证，需要用户提供具体会话才能定位）：

- 会话被 **compaction**（上下文压缩）后，界面只回放压缩后的可见轨迹；
- 长工具输出被 **spill 到外部文件**，该文件不可达时输出呈现为截断；
- 桌面侧**投影缓存陈旧**（本机确有 `cache stays stale` 的 EPERM 记录，见 `04` §F7）导致标题/轨迹提示滞后。

## 3. 用户预期 vs 实际

| 用户预期 | 实际 |
|---|---|
| 两端从同一个地方读，所以内容应该一致 | **读的地方确实一样**（同一个 `$DSH_HOME`、同一批文件、同一个 dsh 版本）；但"能读"≠"会显示"——中间隔着一道**工作区成员资格闸门** |
| 历史对话应该"展示齐全" | 会话 JSONL 一个字节都没丢，但**列表按工作区分组**，未登记或目录已消失的会话被静默剔除，界面上无从进入 |
| 两端应该互相引用 | 不引用。两端是**同一份存储的两个客户端**，没有跨端同步、没有导入导出、没有互相引用 |

## 4. 验收标准（本问题闭环的定义）

- 用户能明确判定读法 A 还是 B（或两者都有），并给出**至少一个具体会话**作为样本。
- 读法 A：能说清"哪些会话本该出现却没出现"，并有一条可复现的**只看不改**的诊断命令产出同样的清单。
- 读法 B：能在样本会话上复现"缺哪一段"，并定位到是 compaction / spill / 缓存三类中的哪一类。
- 改善方案经用户确认后才进入实施（见 [02-方案_跨端会话可见性改善.md](02-方案_跨端会话可见性改善.md)）。
