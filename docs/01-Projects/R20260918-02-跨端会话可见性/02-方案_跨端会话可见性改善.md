## 0. 结论先行

问题分两类，**修法完全不同**：

| 类型 | 本机数量 | 谁能修 | 最省事的修法 |
|---|---|---|---|
| **T1 · cwd 目录已消失**（工作区被改名/移动/删除） | 5 个根会话（涉及 2 个工作区） | **用户自己**，零代码 | **把目录按原路径恢复**（哪怕是空目录），会话应回到列表（**推论，未实测**——本次取证全程只读，未在用户家目录创建任何目录） |
| **T2 · cwd 目录还在，但从没登记进工作区** | 71 个根会话（涉及 16 个项目目录） | **上游 DSH 根治**；本仓可做补登记工具 | 调 `session/create {workspaceId, sessionId}` 补登记（有副作用） |

**推荐落地顺序**：`U1`（用户自助，立刻可做）→ `E1`（本仓只读自检）→ `E3`（文档化）→ 确认后再议 `E2`（写入类补登记）→ `D1/D2`（上游）。

## 1. 层一：用户自助（零代码，立即可用）

### U1 —— 把消失的目录按**原路径**恢复

**依据**：成员资格只要求「会话 header 的 `cwd` 经 `realpath` 后等于工作区 `path`，且该路径是现存目录」（`dsh-workspace/lib/index.js:709-727`、`:102-104`）。**不要求目录里有任何内容。**

> ⚠️ **本条是代码推论，本次未实测**：取证全程只读，没有在 `D:\Users\liaohai1\Desktop\常见问题记录` 或 `D:\obsidian-vaults\项目空间` 建过任何目录。P0 阶段由用户执行并回报结果后，才把本条升级为"已实测"。

**关键好消息**：`workspace.json` 里那两个孤儿工作区的 `sessionIds` **仍然完整保留**（`4111d60d` 4 条、`7381c3cd` 2 条，**实测未丢**）——因为成员过滤只作用于内存视图与对外 API（`lib/index.js:102-104`），`mutate()` 的落盘剪枝**只在下次写这个工作区时**才发生（`lib/index.js:173-191`，代码依据）。

**⚠️ 因此有一条硬性操作顺序**：

> 一旦发现某个项目目录被改名/移动，**先恢复目录，再做别的**。
> 在那之前**不要**对该工作区做重命名、归档、拖拽排序（`insertSessionBefore`）等任何写操作——`mutate()` 会在那一刻把失效的 `sessionIds` **永久剪掉**（`lib/index.js:173-191`）。

**本机待恢复清单**：

| 原路径 | 影响的根会话 |
|---|---|
| `D:\Users\liaohai1\Desktop\常见问题记录` | 4 个 |
| `D:\obsidian-vaults\项目空间` | 2 个 |

（`D:\obsidian-vaults` 已被重组为 `03-工作笔记` / `C01-…` / `C07-…` 等新名字，需确认这两个旧目录是被改名还是被删除。）

### U2 —— 改名前的规避

需要重命名项目目录时：**先在该路径下把会话用不到就不管**，改名后**立刻在原路径建一个同名目录**（或改用"新建工作区 → 在 DSH 里迁移会话"的流程）。当前 DSH **没有**"会话跟随目录改名"的能力。

## 2. 层二：本仓（VS Code 扩展）可做

### E1 —— 会话可见性自检（**只读**，推荐先做）

新增命令 `DeepSeek Harness: 会话可见性自检`，扫描 `$DSH_HOME`，输出三张清单：

| 清单 | 内容 |
|---|---|
| A. 目录已消失 | 会话 id、原 `cwd`、所属工作区、**建议：恢复该目录** |
| B. 未登记根会话 | 会话 id、`cwd`、`createdAt`、`agentPreset`、**建议：补登记** |
| C. 健康统计 | 可见 / 不可见 / 子代理 各自数量，工作区数与存活数 |

**性质**：纯读。不写 `workspace.json`、不碰会话文件、不调任何写类 RPC。
**复用**：扩展已有 `workspaceSnapshot()` / `listWorkspaceSessions()`（`src/serverManager.ts:749-841`），可在此基础上加一个 `src/sessionVisibility.ts`（vscode-free，便于单测）。
**验收**：在本机上跑出的数字必须与 [04-事实_本机会话存储取证.md](04-事实_本机会话存储取证.md) §F5 一致（76 个不可见根会话 / 25 工作区 / 2 个目录消失）。

### E2 —— 一键补登记（**写入类，必须显式授权**）

**技术可行性已核实**（`dsh-api-session-controller/lib/index.js:571-599`、`:408-455`）：

```
1. workspace/create {path: <session.cwd>}     → workspaceId（已有则复用）
2. session/create {workspaceId, sessionId}    → createOrAdopt(sessionId, cwd, checkPersistedIdentity=true)
                                                 → agents.resume({resumeSessionId})
                                              → workspace.attachSession(sessionId)  ← 补登记完成
```

**⚠️ 副作用（必须先讲清再决定）**：

| 副作用 | 说明 |
|---|---|
| 会**真的 resume 会话** | `createOrAdopt` 走 `agents.resume({resumeSessionId})`，不是纯登记；会为该会话拉起 live agent |
| 可能触发**懒迁移** | 目标若是 v0 代际（`session.jsonl.zstd`），resume 会把它迁移成 `session.v3.jsonl.zstd`（`dsh-session-persistence-jsonl/lib/index.js:2486-2511`）。本机 70 个 v0 会话中若被补登记，就会写入新代际文件 |
| `preset` 必须一致 | `assertPresetUnchanged` 会在存储 preset 与请求 preset 不同时报错（`:424`）→ 必须读回存储值再传 |
| `cwd` 必须完全一致 | `observation.header.cwd !== cwd` 直接抛 `ApiSessionCwdConflict`（`:422`）——所以**不能**借补登记把会话挪到别的目录 |
| 写 `workspace.json` | 并发客户端（本机常有 2 个 `dsh web` 同时在跑）可能竞争；实施前必须备份 |

**没有更轻的路径**：工作区 RPC 面只有 `createDirectory / list / pick / archiveSession / create / delete / follow / insertBefore / insertSessionBefore / rename`（`dsh-api-workspace-controller/lib/typert.host.js:130-350`）——**不存在 `workspace/attachSession`**，也没有 unarchive。所以补登记只能借 `session/create`。

**建议做法**（若用户批准）：默认 **dry-run**（只打印计划），加 `--yes` 才真写；先备份 `workspace.json`；一次只处理一个工作区；失败即停。

### E3 —— 文档化（零风险）

把下面两条写进用户可见文档：

1. `README.md` 的「已知行为 / 限制」：**改名或移动项目目录会让该目录下的会话从列表消失**，恢复目录即可复原；恢复前不要对该工作区做写操作。
2. 教程补一节：会话存放位置（`$DSH_HOME/sessions/<项目>/<会话>/session.v3.jsonl.zstd`）与"工作区 = 目录路径"的绑定关系。

**落点**：`README.md` / `README.en.md` + `docs/01-Projects/R20260914-02-DSH内嵌原理与教程/`。

## 3. 层三：必须上游（DSH）修（本仓只能反馈）

| # | 上游问题 | 影响 | 建议修法 |
|---|---|---|---|
| **D1** | `{cwd}` 形态建会话**不 attach 工作区**（`dsh-api-session-controller/lib/index.js:586-593` 只在 `workspace !== undefined` 时 attach） | 71 个根会话永久不可见 | `cwd` 能匹配到既有工作区时自动 attach；或前端一律改用 `workspaceId` |
| **D2** | 历史收养 `bootstrap()` **只跑一次**（`dsh-workspace/lib/index.js:344-347` 受 `state.initialized` 门控） | 一旦漏登记就**不自愈** | 改成可重复的增量收养（或在 `session/create {cwd}` 后触发一次局部收养） |
| **D3** | 工作区路径消失时**静默剔除**成员，界面无任何提示（`lib/index.js:737-747` 仅 `logger.warn`） | 用户表现为"历史对话凭空消失" | 保留成员并在 UI 标记"目录缺失"，允许只读回看；至少把 warn 提升为界面可见提示 |

**本仓不做**：不改 DSH 的 `/api` 信任围栏；不代写上游文件；`E1` 保持只读。
