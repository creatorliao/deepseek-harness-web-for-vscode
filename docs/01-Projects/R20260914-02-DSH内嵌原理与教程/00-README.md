## 核心发现速览（先看这 6 条）

1. **架构的分水岭是一个上游 bug**：VS Code webview 里跨源 iframe 的剪贴板被永久封死（[#182642](https://github.com/microsoft/vscode/issues/182642)），所以"iframe 内嵌"被否决，改成了"**把 DSH 前端直接加载进 webview 文档 + 传输桥**"。
2. **桥的本质是替换浏览器全局对象**：`bridge-client.js` 改写 `fetch` / `WebSocket` / `navigator.clipboard` / `matchMedia`，DSH 前端**完全不知道**自己被桥接了 → 所以能做到"零 fork"。
3. **我们改 DSH 只改两处**：**文档层**（组装 HTML 时改写资产引用 + 注入 CSP/桥/会话预设/覆盖层）与**宿主层**（谁来启动 dsh、怎么认证、怎么调它的 RPC）。**一行 DSH 源码都没改。**
4. **Q4 的关键结论：DSH 官方本来就能收起侧边栏**（收成 56px 轨道），而且**面板窄于 1024px 时会自动收起** —— 零改造。真正的缺口只有两个：折叠状态**不持久化**、官方**没有 0 宽完全隐藏**。
5. **Q5 的关键结论（已实施）**：原来面板落在"当前活动编辑器组"（因为新建/打开会话硬编码 `ViewColumn.Active`）。现已改成**次级侧边栏视图**（A 档）作为默认形态——结构上钉死在主侧边栏对面，用户拖不走；同时**保留编辑器标签页**用于并排对比与宽界面作业，由 `deepseekHarness.openTarget` 决定默认走哪个，全部路径收敛在 `extension.ts` 的 `openUi()` 一个路由点。`engines.vscode` 定为 `^1.105.0`（覆盖 VS Code 1.105.1 与 Cursor 1.128.0 的最小值——注意 `engines` 是**下限**不是设计目标，抬高只会把人挡在门外）。
6. **三个我原本准备用、但核实后并不存在的 VS Code 命令**：`workbench.action.moveActiveEditorToLastGroup`、`moveEditorToLastGroup`、`workbench.action.newGroupRight`。可用的是 `workbench.action.moveEditorToRightGroup`、`moveActiveEditor`（无前缀）、`workbench.action.splitEditorRight`。
