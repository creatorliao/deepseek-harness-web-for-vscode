## 本夹是什么

回答一个问题：**当用户机器上的 dsh 内核版本超出本扩展实测过的范围时，扩展能不能主动告诉用户？**

**背景（一句话）**：扩展**读的是本机全局安装的 dsh**（不打包、不安装、不锁定版本，见 [04-Archives 调查报告](../../04-Archives/20260919-01-插件运行的内核与版本跟随关系调查.md)），所以"能力跟着全局版本走"；但扩展运行时**只知道一条硬编码的下限**，对"版本比我们验证过的更新"**完全无感知**——上游改了内部形态就会静默失效或白屏，用户拿不到任何提示。

**为什么现在提**：上游迭代极快（约一个月走完 `0.1.0-rc.6 → 0.1.6-alpha.2`，其中 3 次破坏性变更都让内嵌面板不可用）。已有的"静默失效"实证：`themeSync` 的 RPC 面在 `0.1.2-rc.1` 就断了，**藏了 5 个版本（v0.3.4–v0.5.3）才被发现**（[13-修复_主题同步静默失效](../R20260820-01-上游DSH版本适配/13-修复_主题同步静默失效_dsh0.1.2起RPC未跟上.md)）。
