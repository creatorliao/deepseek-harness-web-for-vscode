# 总结：界面注入收敛

**日期**: 2026-09-29 ｜ **状态**: 当前
**定位**: 结果记录 —— 做了什么、改了什么、关键决策。

---

## 1. 结论

现场 VOC 提的四件事，**三件已在 0.6.1 修复并装机**，第三件（活动栏孤儿图标）的**根因与边界查清了，但只能防复发 + 给手动清理路径**，因为 VS Code 没有提供可用的 API。

关键事实（实测，不是推断）：**VS Code 1.105.1 没有任何"移除固定视图容器"的命令**。
`workbench.action.pinView` / `unpinView` / `removePinnedViewlet` 在 `workbench.desktop.main.js` 里全部检索不到（各 0 命中）。
所以"活动栏上那两个没图标的 DeepSeek Harness"扩展清不掉 —— 这一条必须如实说，不能假装修好了。

## 3. 关键决策

| 决策 | 取舍 |
|---|---|
| 投放条开关**默认 `true`** | 默认关掉会让已经在用该入口的用户受损（`AGENTS.md` §7.1 对内原则）。代价：用户需要自己关一次 |
| **不**贡献回旧容器 id（`dsh` / `dsh-panel`） | 那不会消除孤儿 pin，只会把它解析成**第三个、第四个可见图标**，更糟。已写成测试用例挡住这个"看起来能修"的错法 |
| **不**动"单编辑器组时打开编辑器标签页会新开一组" | 那是 `editorTab` 形态的既定设计（`src/openTarget.ts:20-29`），且默认形态是 `sidebar`。属范围外，记进 `06-待办` 的决策项 |
| **不**改写 VS Code 的 `state.vscdb` | 私有存储，扩展去写属于越界且不受支持 |
