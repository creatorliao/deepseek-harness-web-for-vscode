# 需求：界面注入收敛

**日期**: 2026-09-29 ｜ **状态**: 已批准（用户 2026-09-29 明确授权"采纳…执行"）
**来源**: [VOC20260929-01](../../03-Resources/VOC20260929-01-活动栏孤儿图标与常驻视图.md)
**定位**: 只回答「做什么」与「做到什么算好」，不含实现细节。

## 1. 背景

用户在某台长期使用本扩展的机器上，活动栏出现**两个名字同为「DeepSeek Harness」但没有图标的条目**；
资源管理器里常驻一条「DSH 上下文（拖文件到此）」且没有任何关闭入口；
活动栏容器与次级侧边栏容器**同名同图标**，hover 也分不出来。

用户的原话（逐字，取自 VOC）：

> 1. 它的拖拽相关功能会新增一个窗格，这并不是我想要的。
> 2. 另外，它会在侧边栏多起一个这个页签也不是我想要的，我希望跟默认的不要冲突。

> 请你帮我调查研究之后，确保它不要破坏我原来 VSCode 相对一致的体验，然后作为 VOC 放回去，升级版本号

## 2. 需求清单

| ID | 需求 | 类别 |
|---|---|---|
| R1 | 活动栏上不应出现本扩展产生、却**渲染不出图标**的条目 | 缺陷 |
| R2 | 扩展往内置资源管理器里加的投放条必须**可以关掉**，且关掉后拖拽/加入上下文的能力仍有其他入口可达 | 体验 |
| R3 | 本扩展贡献的两个视图容器必须能**一眼区分** | 体验 |
| R4 | 上述两类问题不得因后续版本改名而**复发** | 缺陷（防复发） |

## 3. 不在本轮范围

| ID | 不做的事 | 决策原因 |
|---|---|---|
| N1 | 改掉「只有一个编辑器组时打开编辑器标签页会新建一个编辑器组」的行为 | 该行为是 `editorTab` 形态的**既定设计**（`src/openTarget.ts:20-29` 注释写明"always on the right"），且 `openTarget` 默认值是 `sidebar`；改它等于推翻设计意图，须单独立项 |
| N2 | 用程序改写 VS Code 的 `state.vscdb` 来清 pin | 那是 VS Code 私有存储，扩展去写它属于越界且不受支持 |
| N3 | 给"旧容器清理"做一条只弹提示、不做实事的命令 | 禁止空壳宣称 |

## 4. 验收标准

| # | 验收标准（可判定） | 怎么验 |
|---|---|---|
| A1（承 R1） | 仓库里存在一条**机器兜底**的检查，锁死 `contributes.viewsContainers` 里本扩展的容器 id 集合；故意改掉其中一个 id 会让 `npm test` 失败 | 改 `package.json` 的容器 id 后跑 `npm test`，对应用例报红 |
| A2（承 R1） | `README.md` 有「活动栏出现重复的 DeepSeek Harness 图标怎么办」一节，给出可照做的清理步骤 | 打开 `README.md` 搜该标题 |
| A3（承 R2） | 存在设置项 `deepseekHarness.showContextDrop`，默认 `true`；置为 `false` 并重载窗口后资源管理器里看不到投放条 | 设置界面搜该项；改值后重载窗口观察 |
| A4（承 R2） | 投放条关掉后，「添加到 DSH 输入框（@ 引用）」命令仍然存在且可用 | 命令面板搜该命令并可执行 |
| A5（承 R3） | 两个容器的 hover 提示文字不相同，且 `icon` 指向不同文件 | 分别 hover 两个图标；读 `package.json` |
| A6（承 R4） | 版本升到 **0.6.1**，`dist/` 下只有一份带该版本号的 vsix | 看 `dist/` 目录；`npm run package` 输出 |
| A7（承 R4） | 新版本已装进本机 VS Code 与 Cursor | `code --list-extensions --show-versions`、`cursor --list-extensions --show-versions` 都显示 `@0.6.1` |

## 5. 约束

- 不改变 `sidebar` / `editorTab` 的既有语义与默认值。
- 不改变扩展 id、命令 id、既有设置键名（本仓 `AGENTS.md` §7.1 对内原则）。
- 投放条开关的**默认值取 `true`**：默认关掉会让已经在用该入口的用户受损，违反同一节的对内原则。
