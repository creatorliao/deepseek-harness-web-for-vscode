## 1. 30 秒上手

1. **点左侧活动栏的 DeepSeek Harness 图标** → dsh 未运行会**自动启动**（`src/launcherView.ts:538-542`）。
2. 等状态点变**绿色**、文字显示 `dsh x.y.z 运行中`（`src/i18nStrings.ts:29-31`）。
3. 点 **在右侧面板打开** → DSH 聊天界面出现在**右侧次级侧边栏**，编辑器里的文件不会被遮住（`src/launcherView.ts:175`）。

就这三步。之后就在右侧面板里像用网页版一样对话。

## 2. 认识两个界面（这是最容易搞混的地方）

| 界面 | 在哪 | 是什么 |
|---|---|---|
| **启动器** | 主侧边栏（活动栏图标） | 控制面板：状态、URL、版本、升级、按钮、**会话列表**、当前工作区 |
| **DSH UI** | 右侧**次级侧边栏**，或**编辑器标签页** | 官方完整前端（对话、会话、设置、插件、Goal、Workflow） |

**点图标看到的是启动器，不是聊天框。** 聊天界面要么点启动器里的按钮，要么用下面的命令（`src/launcherView.ts:434-435`、`src/chatView.ts:30-32`）。

### 四个打开入口，按场景选

| 场景 | 用什么 |
|---|---|
| 边写代码边聊（不遮编辑器） | 启动器的 **在右侧面板打开**；或命令 **`在右侧面板打开`** |
| 要宽界面 / 并排对比 / 多开 | 启动器的 **在编辑器打开**；或命令 **`在编辑器打开`** |
| 键盘党 | `Ctrl+Shift+P` → 输入 `DeepSeek Harness` 看到全部 6 个命令 |
| 只想点一下 | **状态栏**：未启动时点它=启动；运行中点它=打开面板（`src/statusBar.ts:23-46`） |

> 默认落在哪由设置 `deepseekHarness.openTarget` 决定（默认 `sidebar`）。**两个按钮永远显式指定形态**，不受该设置影响——所以你随时能切。

## 3. 会话管理（启动器下半部分）

| 想做的事 | 怎么做 |
|---|---|
| 开一个新对话 | 点 **`＋新建会话`** → 自动打开绑定该会话的面板（`src/launcherView.ts:494-495`） |
| 回到某个会话 | **点会话整行** → 已开则聚焦，未开则新建面板（`:284`、`src/sessionPanels.ts:57-75`） |
| 改名 | 点行内 **✎** → 输入 → `Enter` 提交（`Esc` 或点别处 = 取消）（`:262-268,361-365`） |
| 收起来不删 | 点行内 **✕** → 归档；底部 **`归档 (N)`** 可展开查看（`:269-274,288-324`） |
| 同时开多个会话 | 在编辑器标签页形态下逐个点会话 → 每个会话一个标签页，**各自独立对话** |

**几个重要语义**：

- **关掉 DSH 标签页 ≠ 停止服务、≠ 删会话**——只关界面，会话还在 DSH 里，重新点会话即可回来（`src/dshPanel.ts:152-159`）。
- **归档 ≠ 删除**，只是从活跃列表挪到归档区。
- 会话列表**每 5 秒自动刷新**（`src/launcherView.ts:14,561-571`），不用手动刷新。
- 会话标题显示优先级：**自定义标题 → 项目文件夹名 → 会话 id**；新建未命名的显示"新会话"（`src/workspaceTracker.ts:47-58`、`src/launcherView.ts:580-581`）。

## 4. 把文件交给 DSH（三条路径）

DSH 的 `@` 引用就是"让模型自己去读这个文件"。三条路径**效果完全等价**：

| 路径 | 操作 | 需要 Shift？ |
|---|---|---|
| **① 快捷键**（最省事） | 光标在编辑器里 → `Ctrl+Alt+A`（macOS `Cmd+Alt+A`）→ 当前文件变成 `@` 引用 | 不需要 |
| **② 右键菜单** | 资源管理器选中文件/文件夹（**可多选**）→ 右键 → **添加到 DSH 输入框（@ 引用）** | 不需要 |
| **③ 拖拽** | 从资源管理器把文件拖到 DSH 输入框 | **必须按住 `Shift`** |

来源：`package.json:76-83,68-75`、`media/bridge-client.js:435-471`。

### 为什么拖拽必须按 Shift

VS Code 在**窗口内拖拽**期间会给 webview 加 `pointer-events: none`，页面根本收不到拖拽事件；按住 `Shift` 是官方给的放行方式（`media/bridge-client.js:204-209`）。不按 Shift 时，文件会被 VS Code 在**编辑器区**打开。

拖拽悬停时页面底部会出现深色提示气泡："松开鼠标，即把拖入的文件作为 @ 引用加入输入框"（`src/i18nStrings.ts:151-153`）。

### 手写 `@` 引用的语法（和拖拽写进去的完全一样）

| 规则 | 例子 |
|---|---|
| 工作区相对路径，**用正斜杠** | `@src/utils/a.ts` |
| 引用整个目录 → **结尾加 `/`** | `@src/utils/` |
| 路径**含空格** → 用双引号包起来 | `@"src/my file.ts"` |
| 一次最多 **20** 个 | 超出的会被截断 |
| 工作区**之外**的文件 → 直接写绝对路径 | `@d:/other/x.ts` |

来源：`src/referenceDrop.ts:42,89-94,121-136`。

> 写进去的是**纯文本 `@路径`**（视觉上没有蓝色 chip），但它与官方 `@` 补全选中文件**逐字节等价**——发给模型的内容相同。机制见 [目录树拖拽到 Composer](../R20260917-01-目录树拖拽到Composer/00-README.md)。

### 失败了怎么办

| 现象 | 含义 | 处理 |
|---|---|---|
| "未能从这次拖拽里识别出可用的文件路径…" | 拖拽没带出可用路径（常见于没按 Shift） | 按住 `Shift` 重拖，或改用快捷键 / 右键 |
| "未能写入 DSH 输入框（输入框可能正忙或不可编辑）。引用已复制到剪贴板…" | 输入框忙/只读 | **直接 `Ctrl+V` 粘贴**（引用已在剪贴板，不会丢） |
| "DeepSeek Harness 界面没有打开…" | 右键时没有活着的 DSH 界面 | 先启动并打开界面，再右键 |
| "没有可加入的文件…" | 快捷键按下时没有已保存的文件在编辑 | 先打开/保存一个文件，或在资源管理器里选中后右键 |

来源：`src/i18nStrings.ts:154-165`、`src/dshUi.ts:83-88`。

## 5. 升级 dsh

1. 启动器在**有新版本时**才出现一行按钮：`最新版更新：x.y.z →` 或 `预览版更新（next）：x.y.z →`（`src/launcherView.ts:166-167`）。
2. 点它 → 弹出选项（按你的安装方式推荐命令、npm global、npx、**复制命令**）（`src/versionCheckService.ts:130-143`）。
3. 选推荐项 → 命令**只预填进终端，不会自动执行**，需要你按回车（`src/versionCheckService.ts:163-166`）。

**注意**：版本检查每 24 小时一次、离线静默失败，所以刚启动可能还没出现升级提示；稍后会自动刷新（`src/extension.ts:143-146`）。

## 6. 停止、重载与"什么会被保留"

| 你做的事 | 服务 | 会话数据 | 面板/标签页 |
|---|---|---|---|
| 关闭 DSH 标签页 | **继续运行** | 保留 | 关闭 |
| 命令 `停止 DeepSeek Harness` / 启动器 **停止** | 停止 | 保留（在磁盘） | 界面变覆盖层 |
| **重载窗口**（同工作区） | **自动重启** | 保留 | **自动恢复**（各自绑回原会话） |
| 切换到**另一个文件夹** | 冷启动 | 保留 | **全部关闭**（有意行为） |

来源：`src/extension.ts:111-172`、`src/sessionPanels.ts:93-97`、`src/dshPanel.ts:152-159`。

> **想让 DSH 以你的项目为默认工作区**：先在 VS Code 里打开那个文件夹——启动器底部会显示当前工作区名（`src/launcherView.ts:611-614`）。没打开文件夹时 DSH 用主目录（`src/commands.ts:10-12`）。

## 7. 常见问题

**Q：点活动栏图标后，为什么右边没有聊天框？**
A：活动栏打开的是**启动器**。点启动器里的 **在右侧面板打开**，或用命令 `在右侧面板打开` / `在编辑器打开`。

**Q：命令 `在右侧面板打开` 之后，界面跑到编辑器标签页了？**
A：这是**有意的回落**：次级侧边栏被隐藏、或被其它视图占用时，扩展会弹中文警告并改用编辑器标签页，而不是让你对着无反应的面板发呆（`src/extension.ts:71-79`）。用命令 `在编辑器打开` 是等价的显式选择。

**Q：面板一直显示"启动中…"或白屏？**
A：先看状态栏——若为红色"DSH 错误"，点它重试。历史上有两类已修复问题：侧边栏状态卡在 Starting（[修复记录](../R20260817-01-桥架构与IDE内嵌/12-修复_侧边栏状态卡在Starting.md)）与启动超时/自动探测失效（[修复记录](../R20260817-01-桥架构与IDE内嵌/13-修复_dsh启动超时与自动探测失效.md)）。若你的 dsh 装在非标准位置，设置 `deepseekHarness.dshPath`。

**Q：提示"dsh x.y.z is not supported"？**
A：本扩展要求 dsh **≥ 0.1.2-rc.1**，更旧的会被明确拒绝而不是半坏着启动（`src/serverManager.ts:479-485`）。按 README 的兼容表升级。

**Q：`Ctrl+Alt+A` 没反应？**
A：两个前提——光标要在**编辑器**里（`when: editorTextFocus`），且文件必须是**已保存的本地文件**（untitled 未命名缓冲、diff 视图没有可指向的路径，会被忽略并给提示，`src/commands.ts:56-59,108-111`）。也可能是键位被别的扩展占用：在「键盘快捷方式」里搜 `addToContext` 改键。

**Q：拖文件进去没反应？**
A：**按住 `Shift`** 再拖。不按 Shift 时 VS Code 会在编辑器区打开该文件。也可以改用快捷键或右键（见 §4）。

**Q：为什么内嵌界面里没有浏览器那样的授权弹窗就能读写剪贴板？**
A：剪贴板经扩展宿主转发（`vscode.env.clipboard`），因此与扩展同级信任，没有浏览器授权弹窗。这一点 [README.md](../../../README.md):40 已声明；数据外发边界见 [R20260918-01 的第三层分析](../R20260918-01-插件配置与数据外发调查/03-分析_数据外发与网络边界.md)。

**Q：想让 DSH 用浏览器里的同一个实例？**
A：默认就是——两者共用 `~/.dsh`（会话、设置互通）。用命令 `在浏览器中打开` 会用系统浏览器打开**带启动令牌**的本机地址（`src/commands.ts:81-90`）。

**Q：主题不跟随，或我想让面板用 DSH 自己的主题？**
A：设置 `deepseekHarness.themeSync`。⚠️ 目前设成 `off` **并不能真正停止跟随**（`matchMedia` 那条通道不受它控制），原因与整改建议见 [R20260918-01 §3.1](../R20260918-01-插件配置与数据外发调查/02-分析_配置项必要性与改进建议.md)。

## 8. 明确不属于本插件的事（省得找错地方）

| 你以为在这里，其实不在 | 在哪 |
|---|---|
| 模型选择、会话内容、插件、Goal/Workflow、DSH 设置 | **DSH 官方界面里**（本插件只负责启动与内嵌） |
| 安装/升级 dsh 本体 | npm（插件只帮你**预填**命令） |
| 会话数据存在哪、发不发出去 | `~/.dsh` 与 dsh 内核行为；边界见 [R20260918-01](../R20260918-01-插件配置与数据外发调查/03-分析_数据外发与网络边界.md) |
| 编辑器里"文件被打开"这类 VS Code 行为 | VS Code 自身（例如不按 Shift 拖拽会在编辑器打开文件） |

