## 2. (a)(b) 命令清单与功能

| # | 命令 id | 命令面板标题 | 它做什么 | 实现 |
|---|---|---|---|---|
| 1 | `deepseek-harness-for-vscode.start` | 启动 DeepSeek Harness | 启动 `dsh web` → 按 `openTarget` 打开界面 → 弹信息提示带 URL；失败弹错误提示 | `src/commands.ts:67-76` |
| 2 | `deepseek-harness-for-vscode.stop` | 停止 DeepSeek Harness | 停掉子进程 → 提示已停止（**会话数据保留在 DSH 里**） | `src/commands.ts:77-80` |
| 3 | `deepseek-harness-for-vscode.openBrowser` | 在浏览器中打开 | 用系统浏览器打开**带 launch token 的本机 URL**（`browserUrl ?? serverUrl`）；未运行则警告"未在运行" | `src/commands.ts:81-90` |
| 4 | `deepseek-harness-for-vscode.openChatView` | 在右侧面板打开 | 聚焦**次级侧边栏**的 DSH 视图（失败则警告并回落编辑器标签页） | `src/commands.ts:91-93` → `src/extension.ts:71-79` |
| 5 | `deepseek-harness-for-vscode.openPanel` | 在编辑器打开 | 在**最右侧编辑器组**打开 DSH 标签页（可多开） | `src/commands.ts:94-96` → `src/extension.ts:62-65` |
| 6 | `deepseek-harness-for-vscode.addToContext` | 添加到 DSH 输入框（@ 引用） | 把资源管理器选中项（或当前文件）转成 `@` 引用写进 DSH 输入框 | `src/commands.ts:97-114` |

**关于第 6 个命令的两种调用形态**（同一命令，两条入口）：

- 资源管理器右键 → 传入点击项 + 整个选择（`uri` / `uris`）；
- 快捷键 → **不传参数**，回退到"当前正在编辑的文件"，且**只接受 `file:` 方案**（未保存的 untitled、diff 视图没有可指向的路径，`src/commands.ts:56-59`）。

两者都没有可用文件时弹中文提示（`src/commands.ts:108-111` → `src/i18nStrings.ts:163-165`）。

## 3. (c) 快捷方式

### 3.1 键位（清单里只注册了 1 个）

| 键位 | 平台 | 条件 | 命令 |
|---|---|---|---|
| `ctrl+alt+a` | Windows / Linux | `editorTextFocus`（光标在编辑器里） | `addToContext` |
| `cmd+alt+a` | macOS | 同上 | 同上 |

来源：`package.json:76-83`。键位可在 VS Code 的「键盘快捷方式」里自行修改（[README.md](../../../README.md):34）。

## 6. 状态栏按钮

一个常驻项（左侧，优先级 100，`src/statusBar.ts:14`），**文字与点击行为随状态变化**：

| 状态 | 显示 | 点击后 | tooltip |
|---|---|---|---|
| `stopped` | `$(circle-outline) DeepSeek Harness: 启动` | 启动 | 启动 DeepSeek Harness |
| `starting` | `$(sync~spin) DeepSeek Harness 启动中…` | **无命令（不可点）** | 正在启动 DSH 服务 |
| `ready` | `$(server) DSH <url>` | **在编辑器打开** | 点击打开面板 |
| `error` | `$(error) DSH 错误` | **重试启动** | 启动失败，点击重试 |

来源：`src/statusBar.ts:23-46`；文案 `src/i18nStrings.ts:88-111`。

> ⚠️ **与 `openTarget` 设置的交互（一处不一致）**：状态栏在 `ready` 时绑定的是**命令 `openPanel`**（`src/statusBar.ts:8,36`）——即**恒为编辑器标签页**，**不读** `deepseekHarness.openTarget`。这与 [AGENTS.md](../../../AGENTS.md) §7「所有"打开界面"的路径必须收敛到 `openUi()` 这一个路由点，否则设置会在一部分路径上生效、另一部分被静默忽略」的口径冲突：默认 `sidebar` 的用户从状态栏点击，拿到的是编辑器标签页。
>
> 对比：启动器两个按钮的"显式指定"是**已文档化**的有意设计（`package.nls.json:10` 明说"启动器面板里的两个按钮可以随时显式指定，不受此项影响"）；状态栏这一处没有对应说明，tooltip 也只写"点击打开面板"（`src/i18nStrings.ts:106-108`）。**建议**：要么让状态栏走 `openUi()`，要么把它也明确文档化为"始终在编辑器打开"。

## 7. 启动器视图的全部按钮（7 类 + 会话行）

| 按钮 | 显示条件 | 行为 | 来源 |
|---|---|---|---|
| `有新版本：x.y.z →`（latest 通道） | `ready` **且**确有新版 | 弹升级选择（QuickPick） | `src/launcherView.ts:166`、`:488-489` |
| `预览版更新（next）：x.y.z →` | `ready` 且 next 通道确有新版 | 同上，走 next 通道 | `src/launcherView.ts:167`、`:489` |
| **在右侧面板打开**（主按钮） | `ready` | 聚焦次级侧边栏的 DSH 视图 | `src/launcherView.ts:175`、`:490-491` |
| **在编辑器打开**（次按钮） | `ready` | 最右侧编辑器组开标签页 | `src/launcherView.ts:177`、`:492-493` |
| **停止 DeepSeek Harness**（次按钮） | `ready` | 停子进程 | `src/launcherView.ts:178`、`:486-487` |
| **启动 DeepSeek Harness**（主按钮） | `stopped` / `error` | 启动 | `src/launcherView.ts:180`、`:482-485` |
| `＋新建会话` | `ready` | 建新会话并打开绑定它的面板 | `src/launcherView.ts:184`、`:494-495` |

**会话行**（每行三个可点区域，`src/launcherView.ts:241-285`）：

| 区域 | 行为 |
|---|---|
| 整行（圆点 + 标题 + 时间） | 打开/聚焦该会话的面板（`:284`） |
| ✎ 图标 | 内联重命名（`:262-268`） |
| ✕ 图标 | **归档**该会话（`:269-274`） |

**归档区**：标题 `归档 (N)` 可点击展开/折叠，展开状态在 5s 轮询重绘中保留（`src/launcherView.ts:216,288-324`）。

**底部页脚**：当前工作区名，或"未打开文件夹 — DSH 将使用主目录"（`src/launcherView.ts:189,611-614`；文案 `src/i18nStrings.ts:71-76`）。

**状态点**：灰=未启动、黄闪=启动中、绿=运行中、红=错误（`src/launcherView.ts:104-107`）。

**两条容易被忽略的行为**：

1. **打开启动器视图会自动启动 dsh**（`src/launcherView.ts:534-542`）——点活动栏图标即等于"我要用 DSH"，`start()` 幂等，重复点击安全。
2. **会话列表每 5 秒轮询**（`SESSIONS_POLL_MS = 5000`，`src/launcherView.ts:14,561-571`），只在"视图打开且服务就绪"时运行。

## 8. DSH 界面内的功能点

### 8.1 覆盖层按钮（服务没起来时）

DSH 视图/标签页在服务非就绪时显示一个覆盖层（`src/dshUi.ts:126-159`）：

| 覆盖层状态 | 文案 | 按钮 |
|---|---|---|
| `stopped` | DSH 服务未启动 | **启动 DeepSeek Harness** |
| `starting` | DeepSeek Harness 启动中… | 无 |
| `error` | DSH 错误：{message} | **启动**（重试） |
| `ready` | 覆盖层隐藏 | — |

来源：`src/dshUi.ts:147-157`；文案 `src/i18nStrings.ts:78-86`。

### 8.2 桥提供的能力（页面里直接可用）

| 能力 | 说明 | 来源 |
|---|---|---|
| `fetch` / `WebSocket` | 页面的 API 调用经宿主代发到本机 dsh（页面自己不能直连外网） | `media/bridge-client.js:73-107,138-174`、`src/bridgeHost.ts:39-60` |
| 剪贴板读写 | 复制/粘贴走 `vscode.env.clipboard`（webview 默认屏蔽 iframe 剪贴板） | `media/bridge-client.js:176-196`、`src/bridgeHost.ts:61-76` |
| 主题跟随 | 编辑器主题变化即时推给页面，不重载 | `media/bridge-client.js:52-71,528-538` |
| 会话预设 | 打开时把 IDE 工作区的会话写进 `dsh.sessions.current` | `src/workspaceTracker.ts:37-39` |

### 8.3 拖拽 → `@` 引用（功能点，含提示气泡）

| 环节 | 行为 | 来源 |
|---|---|---|
| 识别 | 只接管 VS Code 资源拖拽（`application/vnd.code.uri-list` 等）；**系统文件拖入仍走 DSH 自己的附件上传**，编辑器文本选区不接管 | `media/bridge-client.js:219-254` |
| 提示 | 悬停时在页面底部显示深色气泡"松开鼠标，即把拖入的文件作为 @ 引用加入输入框" | `media/bridge-client.js:279-298`；文案 `src/i18nStrings.ts:151-153` |
| 落下 | 把原始 mime 负载转给扩展宿主解析（路径语法在宿主侧，有单测） | `media/bridge-client.js:455-471` |
| 写入 | 用 DSH 前端自己的粘贴命令写入 composer（Lexical 编辑器，直接改 DOM 会被回滚） | `media/bridge-client.js:305-433` |
| 失败降级 | 输入框忙/只读时：**把引用复制到剪贴板**并中文提示按 Ctrl+V | `src/dshUi.ts:83-88`；文案 `src/i18nStrings.ts:157-159` |
| 无界面时 | 提示"界面没有打开，请先启动并打开 DSH 界面" | `src/dshUi.ts`（调用点 `src/extension.ts:180-187`）；文案 `src/i18nStrings.ts:160-162` |

### 8.4 `@` 引用语法（用户可手写，等价于拖拽）

| 规则 | 例子 | 来源 |
|---|---|---|
| 工作区相对路径 + **正斜杠** | `@src/utils/a.ts` | `src/referenceDrop.ts:89-94,110-113` |
| 目录加**尾随斜杠** | `@src/utils/` | `src/referenceDrop.ts:92` |
| 路径含空格 → 用双引号包起来 | `@"src/my file.ts"` | `src/referenceDrop.ts:93` |
| 一次最多 **20** 个引用 | 超出部分被截断 | `src/referenceDrop.ts:42,103` |
| 工作区**之外**的文件保留绝对路径 | `@d:/other/x.ts` | `src/referenceDrop.ts:121-136` |
| 含双引号或控制字符的路径**跳过**（不转义，因为转义会造出不存在的路径） | — | `src/referenceDrop.ts:61-81` |

## 9. (d) 自动触发点（不需要用户操作）

| 触发 | 发生什么 | 来源 |
|---|---|---|
